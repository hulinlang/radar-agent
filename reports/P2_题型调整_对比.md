## 三、还没解决 / 需要你拍板的点

1. **`calc` 的"公式形式"由谁判？**
   合并后只剩 `numeric`（数值对不对）。我试过给 calc 配 keypoints，**验完自己撤掉了**：
   计算题的答案模板只生成「公式/代入/最终答案」三行，**没有位置放语义要点**；
   而拿 LaTeX 当要点极脆（`\frac{c}{2B}` 与 `c/(2B)` 是同一个式子但字符串不同）。
   → 现状：公式形式只能靠**裁判 LLM（D4）或人工抽检**判。若要做成机器判，得先定 `basis` 字段（人写一句依据）。

2. **解析与字母不一致仍会被静默放过**（判分只看字母）。已用 keypoints 兜一层，
   但那只能证明"解析里提到了这些依据"，不能证明"解析支持的是这个字母"。

3. **`term` 正向问法会让大部分术语题的 regime 变成 `universal`**（题面没有体制线索，
   而 `E_REGIME_SURFACE` 要求具体体制必须出现表面词）。
   我的判断：这是**对的**——术语本身多属普适；体制差异交给 `contrast`/`regime_trap`。
   但若你认为术语也应按体制分层统计，就得在题面里补体制词（"机载雷达里的 STAP 是什么？"，见 txt_000306）。

4. **数据卫生**：草稿里我一度把 Markdown 强调符 `**…**` 写进了解析文本 → 已修正。
   建议加一条 warning 级断言 `W_MARKDOWN_IN_ANSWER`（答案/解析里出现 `**`/`##`/`|-` 等排版符即告警），
   否则这类噪声会**静默进入训练集**（模型可能学会输出星号）。

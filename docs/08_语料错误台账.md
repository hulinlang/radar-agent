## 二、第 3 条（v_u 差 2 倍）的完整推理 —— 值得单独看

这是本台账里**最危险**的一条，因为它不涉及"算错数"，而是**定义歧义**，且教材内部自相矛盾：

```
脉冲多普勒雷达：每个脉冲采一次样 → 采样率 = PRF = f_r
多普勒频移：    f_d = 2v / λ
奈奎斯特：      |f_d| ≤ f_r / 2          ← 教材 4.3.2.2 原文：f_dmax ≤ (1/2)·f_r
联立：          2v/λ ≤ f_r/2  →  v ≤ λ·f_r / 4
```

→ **v_u = λ·PRF/4**，注册表 `_f_unambiguous_velocity()` 实现为 `lam * prf / 4.0` ✓

而教材式(4.3.5) 写 `ν_U = (λ/2)·f_r` = λ·PRF/2 —— **是上式的 2 倍**。
两种可能：① 教材把"不模糊**区间宽度**"（−λf_r/4 ~ +λf_r/4，总宽 λf_r/2）当成了"最大不模糊速度"；
② 单纯笔误。无论哪种，**它与自己那句 f_dmax ≤ f_r/2 不自洽**。

**处置（已定，2026-09-15）**：
- 真值一律走注册表 **λ·PRF/4**（物理自洽，且与教材 4.3.2.2 一致）；
- 涉及 v_u 的题，evidence **不引式(4.3.5)**，改引 4.3.2.2 的表述；
- notes 里写明该冲突；
- 例：λ=3 cm、PRF=10 kHz → **75 m/s**（不是 150）。

> 面试延伸：这正好是"**为什么真值必须由程序算、而不能从语料抄**"的最佳例子 ——
> 语料会错、会自相矛盾，而可执行的代码 + 可复现的推导不会。

## 三、发现新冲突时的处理流程

1. **先复算**（用 `scripts/p3_corpus_query.py formula <name> --try-compute "…"` 或 `formulas.evaluate`），
   确认是自己算错还是语料错 —— **"我记得应该是"不算证据**。
2. **找第二信源**：教材 vs 毫米波语料互为印证；两份都错时才考虑外部常识。
3. **登记本台账**（补充一行，含判定依据）。
4. **在题的 `notes` 里写明冲突**，不要静默改答案。
5. 若涉及**公式注册表**的正确性 → 立即上报主对话（影响所有用该公式的题）。

## 四、已知的"形似错误"（**不是**错误，别误判）

- `radar-basics/radar-equation.md` 里的 dB 换算与教材不同（用 10log 而非 20log 处理功率/幅度）
  → 这是**功率 vs 幅度**的正确差异，不是错误。
- 教材 p142 "实际单天线雷达系统中不模糊……" 之后有截断 —— 是 MinerU 抽取的段落切分，非原文缺失。

- ⭐ **mmWave `target-detection.md` 的 SO-CFAR 描述是**正确的**，别误判**（2026-09-16）：
  文档写"选择左右窗口中较小的噪声估计值"、`Z = min(Z_left, Z_right)`，
  优点是"杂波边缘性能好 / 虚警率低 / 适应非均匀背景"，对比表里 **多目标 ⭐⭐、杂波边缘 ⭐⭐⭐⭐⭐**。
  这是标准结论（SO-CFAR = Smallest Of = 选小 → 抗杂波边缘，**代价是多目标性能差**）。
  ⚠️ 易错点：紧邻的**上一段是 GO-CFAR**（Greatest Of = 选大 → 抗多目标遮蔽，
  适用场景写的是"密集交通/多目标环境/城市道路"）。
  两者挨着且句式相同，**很容易把 GO 的描述当成 SO 的**，从而误判"文档把适用场景说反了"
  —— 2026-09-16 一个子代理就踩了这个坑。看到"适用场景"时**先看它属于哪个小标题**。

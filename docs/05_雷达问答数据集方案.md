> 制定日期：2026-09-14　|　状态：**主要决策已由用户敲定，待开工执行**
> 上游依据：`docs/00_行为规范.md` v1.0（§3 输出结构 / §5 实验验证 / §5.10 RAG-Agent 专项 / §8 安全合规）

## 一、这一步要解决什么（Why）

**做什么**：为 `Qwen3-VL-2B-Instruct` 构造一套**雷达领域问答数据集**，分文本与图表两路，并建立可机器判分的评测集。

**在链路中的位置**：它是「微调」的输入、也是「前后对比」的标尺。没有它，后续的 LoRA 微调只能凭感觉说"好像懂了"，评测也无从谈起。

**不做的后果**：
- 微调没有训练信号 → 只能拿通用数据凑数，模型学到的不是雷达知识而是通用对话（且很可能指令格式退化）；
- 没有冻结的评测集 → 「微调后准确率提升了」这句话**无法成立**，因为你会不自觉地照着测试集调数据（规范 §5.4 明令禁止）；
- 图表样本与文本样本混在一起 → 提升无法归因到"文本知识"还是"看图能力"（违反 §5.9 "只改一个变量"）。

## 二、已敲定的决策（2026-09-14）

| 编号 | 决策点 | 结论 | 依据 / 代价 |
|---|---|---|---|
| **执行序** | 阶段执行顺序 | **微调前移、RAG 后置**：`语料(P2) → 数据集(P3) → 微调(P5) → 前后对比(P7 部分) → 基线RAG(P4) → Agent(P6) → RAG评测(P7) → 部署(P8)` | 用户拍板。RAG 后置使"无检索基线"更干净（§5.10）；代价是 RAG 相关问题延后暴露 |
| **D6** | 雷达子方向聚焦 | **信号处理基础**（匹配滤波 / 脉冲压缩 / 模糊函数 / 分辨率 / 雷达方程 / 多普勒） | 用户拍板。优点：**最通用、数值真值最易程序验证**、图表生成成本最低；代价：与 SAR/STAP 相比"亮点"稍平 |
| **D8** | 数据合成是否可用云端 LLM | **允许，且允许外发已公开教材/论文原文** | 用户拍板。**附带 5 条护栏，见 §7**。代价：版权与数据外发风险由使用者承担 |
| **V0 形态** | 首个小样的形态 | **文本与公式为主，必要时附示意图** | 用户拍板。先跑通「数据→训练→评测」链路，图表作为辅助而非主体 |
| **CoT / 思维链** | **不做**（V0 与后续均不做） | 用户 2026-09-14 拍板。依据：实测当前权重**无 thinking 模式**（§5.8）；且本项目定位为**小成本微调**，CoT 属"从零教"的大成本改造 |
| 继承 | 多模态深度（D2） | 主链路纯文本 + 图表问答**独立实验**；LoRA 时视觉塔全程冻结 | 规范 §12 已决 |
| 继承 | 评测集隔离（§5.4） | **评测集必须先于微调冻结**，训练前做去污染检测 | 规范硬性条款，不可协商 |

> ⚠️ **执行序与执行顺序**：阶段编号（P2/P3/P4/P5…）**保持不变**，仅调整**执行先后**。
> 这样既不改动已有文档引用，也避免"P4 到底是 4 还是 0"这类混乱。

## 三、三个集合必须物理隔离

这是本方案最重要的一条设计。

| 集合 | 内容 | 用途 | 是否参与训练 |
|---|---|---|---|
| **SFT-T** | 纯文本问答（概念 / 计算 / 公式 / 术语） | 微调主链路 | ✅ |
| **SFT-V** | 图表问答（图 + 问 + 答 + 图真值） | **独立受控实验**，只回答"2B 在雷达图表上学到东西没有" | ✅（但在**独立轮次**中训练，不与 SFT-T 混） |
| **EVAL** | 冻结评测集，含**不可答子集** | 前后对比的**唯一标尺** | ❌ **永不参与训练，永不用于调参** |

**为什么必须隔离**：若把图表样本混入主训练集，则微调后的任何提升都**无法归因**——
是文本知识带来的，还是模型学会了"看图"？这是规范 §5.9「任何对比实验必须先声明只改了一个变量」在多模态上的直接推论。

**物理隔离的实现**：三个集合分别落盘为独立 JSONL 文件，并在文件名与 `id` 前缀上区分
（`txt_*` / `vis_*` / `eval_*`），由脚本断言**训练加载器不可能读到 `eval_*`**。

## 四、数据来源三层

### L1 程序合成（主力，**不依赖教材**）

利用雷达领域的一个天然红利：**大量真值可以程序算出来**。

- **做法**：图形用代码绘制（numpy + PIL，**注意本机 `qwen3vl` 环境无 matplotlib**），
  答案由**同一份生成参数**计算得出 → 真值与图形严格同源，可机器验证。
- **优势**：可无限生成、确定性可复现（固定 seed）、零版权风险、**不被 P2 语料阻塞**。
- **已可复用的资产**：
  - `src/vl_probe.py` —— 已验证的「numpy+PIL 合成图 + 真值写死」范式（无 matplotlib 依赖）
  - `F:\AI RADAR\spaceborne.m` —— 前序**星载雷达 STAP** 仿真，含大量可直接借用的参数与公式：
    `ΔR = c/2f_s`（距离分辨率）、`R_u = c/2f_r`（最大不模糊距离）、`R_max = sqrt(H(2R_e+H))`、
    3dB 波束宽度、多普勒、相干脉冲数 K、噪声功率 `P_n = kT₀B·F_n`、Khatri-Rao 积实现。

**信号处理基础（D6 选定）的 L1 生成器清单**：

| 生成器 | 产出图 | 可自动配对的知识点 |
|---|---|---|
| `gen_pulse_compression.py` | LFM 时域/频域波形 + 脉压后主瓣旁瓣 | 脉压增益 = BT、时宽带宽积、加窗对旁瓣的抑制、主瓣展宽代价 |
| `gen_ambiguity.py` | 模糊函数二维图 | 距离-多普勒联合分辨、模糊瓣位置、单脉冲 vs 脉冲串模糊 |
| `gen_radar_equation.py` | 探测距离 vs 参数曲线 | 雷达方程、R∝(P_t·G²·λ²·σ)^(1/4)、各参数对 R_max 的敏感度 |
| `gen_resolution.py` | 两目标可分辨/不可分辨对比图 | 距离分辨率 ΔR=c/2B、多普勒分辨率 Δf_d=1/T |
| `gen_doppler.py` | 多普勒频率/速度模糊示意 | f_d=2v/λ、速度模糊 v_u=λ·f_r/4 |

**数值题生成器**：`gen_calc_qa.py` —— 从参数模板批量生成计算题，答案**由公式算出**，
并附 `answer_check`（数值 + 单位 + 容差）+ `solution_steps`。

### L2 教材/论文抽取（等语料）

- **做法**：MinerU 解析 → 文本切分 + **图表单独抽出**（图表要成对保存：图像 + 图注 + 所在页码）。
- **用途**：提供**术语规范**（中英文对照）与**证据句**（`evidence.quote`），
  以及为云端合成提供"素材段落"。
- **依赖**：`data_raw\` 投料（**当前为空**）。工具链 `magic_pdf` **尚未安装**。
- **风险**：公式与表格解析质量不可控（规范 §9.2 已列为高风险）→ **必须先小样人工抽检**。

### L3 人工构造（质量天花板）

- 教材自测题改写、你手写的"边界题"与"陷阱题"。
- **不可替代的作用**：定义术语口径、把关不可答问题集、抽检 L1/L2 产出质量。

> **关键结论：L1 与 L3 现在就能开工，不被 P2 阻塞。** 只有 L2 在等语料。

## 五、对话格式与统一 schema（**全部对照模型规范实测**）

训练集与评测集**共用同一结构**，评测集仅多一个 `split: "eval"` 及更严格的必填项。
这样对比脚本一行通用，也才能把 §5.2「每个数字可回溯」落到多模态上。

> **本节所有格式结论均来自实测**，不是按 Qwen 系列惯例推断。
> 证据：`logs/probe/p3_chat_template_probe.txt`、`logs/probe/p3_cot_probe.txt`；
> 复现脚本：`scripts/p3_probe_chat_template.py`、`scripts/p3_probe_cot.py`（只读本地权重，不下载）。
> 依据是本项目第一次静默错误——"按 base 版惯例推断 `eos_token`"。

### 5.0-B 渲染格式（实测，`apply_chat_template` 原样输出）

```
<|im_start|>system\n{system}<|im_end|>\n
<|im_start|>user\n{user}<|im_end|>\n
<|im_start|>assistant\n{assistant}<|im_end|>\n
...
```
`add_generation_prompt=True` 时末尾追加 `<|im_start|>assistant\n`（**不带** `<|im_end|>`）。

**文本 ↔ id 对照**：`<|im_start|>`=151644 · `<|im_end|>`=151645 · `\n`=198 · `user`=872 · `assistant`=77091

### 5.0-C 图像 → 视觉 token 的展开规则（实测 `Qwen3VLProcessor`）

| 输入尺寸 | grid_thw | `<|image_pad|>` 展开数 | 该回合 input_ids 总长 |
|---|---|---|---|
| 224×224 | [1,16,16] | 64 | 78 |
| 256×256 | [1,16,16] | 64 | 78 |
| **448×448** | [1,28,28] | **196** | 210 |
| 512×512 | [1,32,32] | 256 | 270 |
| 1024×1024 | [1,64,64] | 1024 | 1038 |
| 300×700 | [1,44,18] | 198 | 212 |

- **公式**：`视觉 token 数 = (H_px / 32) × (W_px / 32)`，H/W 会被规整到 **32 的倍数**（= patch 16 × merge 2）
- **最小 256×256（64 token）**：`shortest_edge = 65536` 像素 → 小于此会被**上采样**，
  所以"用更小的图省 token"**无效**（224×224 实测仍是 64 token）
- 上限 `longest_edge = 16777216`（4096×4096），超出会下采样
- 单图 196 token：2048 上下文下 10 张图就吃掉近千 token，**必须给输出留预算**

### 5.3 为什么这几个字段是必需的

| 字段 | 作用 | 缺失后果 |
|---|---|---|
| `answer_check.unit` + `tol` | 机器判分 | 雷达数值题极易在 **km/m、Hz/kHz、dB/线性** 上翻车，无单位则判分无意义 |
| `answer_check.type` | 选择判分器 | 数值/符号/选择/拒答 的判分逻辑完全不同，混用会得出错误"准确率" |
| `evidence.quote` | 可溯源 | 评测集必填；否则答案没有出处，无法人工复核 |
| `image.sha256` + `figure_truth.params` | 图的身份与真值 | 否则无法证明"评测用的图" = "训练过的图"，也无法在图重新生成后核对真值是否同步 |
| `subdomain` | 分层统计 | 否则某一方向的样本会淹没整体准确率，掩盖真实弱项 |
| `meta.created_by` | 来源审计 | D8 决策要求可追溯哪些样本经云端生成 |

### 5.4 消息层的三条铁律

1. **渲染必须走 `apply_chat_template`，禁止手写 `<|im_start|>`** —— 手写迟早与模板漂移（静默错误）。
2. **`content` 允许两种形态**：`str`（纯文本）或 `list[dict]`（多模态交错）。
3. **"字符串拼接造数据"已被验证无损**（实测 A2）：
   `apply_chat_template(tokenize=True)` 与 `tokenizer(渲染后的字符串, add_special_tokens=False)`
   得到**逐 id 完全相同**的结果，且 `decode` 能无损还原原串。
   → 所以生成器可以**先生成字符串、再统一 tokenize**，不必每条都去调模板接口。

### 5.5 图表 + 文本的写法（多模态交错）

```json
{"role": "user", "content": [
    {"type": "image"},
    {"type": "text", "text": "图中第一个目标的距离约是多少？"}
]}
```
渲染结果（实测）：
```
<|im_start|>user\n<|vision_start|><|image_pad|><|vision_end|>图中第一个目标的距离约是多少？<|im_end|>\n
```
- **图片顺序 = `content` 里 `image` 出现的顺序**（模板用全局计数器编号），**与文件名无关**。
- `apply_chat_template(..., add_vision_id=True)` 会在每张图前插入 `Picture N: ` 文本前缀。
  **多图题建议开启**，否则"图1/图2"的指代只能靠位置推断。
- 训练数据里**不要**自己写 `<|vision_start|>` 等标记——那是模板的事，写了会变成内容，
  且立刻触发 §5.9 的注入断言。

### 5.6 答案规范（assistant 侧：人读得懂 + 机器可判分）

实测基线行为：模型原生输出**啰嗦 Markdown + LaTeX**（`###`、`$$`、`---` 满天飞），
P0 也记录过"一问写 974 token"。所以**答案格式必须靠训练约束**，不能指望 prompt 一次压住。

建议的统一答案模板：

| 任务类型 | assistant 内容模板 | 判分方式 |
|---|---|---|
| `calc` 计算题 | `公式：<latex>` → `代入：<latex>` → `最终答案：<数值> <单位>` | 正则抽 `最终答案：` + 数值/单位/容差比对 |
| `choice` 选择题 | `最终答案：X`（单个字母） | 完全匹配 |
| `concept` 概念题 | 自由文本，**≤ 120 字** | 要点覆盖（关键词集合）+ 可选 LLM 判分 |
| `formula` 公式题 | `公式：<latex>` → `最终答案：<latex>` | LaTeX 符号化归一后比对 |
| `term` 术语题 | `最终答案：<中文名>（<英文全称>）` | 归一化后匹配 |
| `unanswerable` | **固定拒答句式**（见 R10） | 完全匹配 |

> **为什么要固定模板**：① 判分器可写死、不依赖 LLM；② 训练信号一致，2B 更容易学会；
> ③ 出问题时能一眼区分"格式崩了"还是"知识错了"——这正是 §八 指标分层的前提。

### 5.7 公式标识：能做什么、不能做什么

> 直接回答提问：「公式是否可以单独用一个特殊字符来标识？」
> **结论：不能新增 special token；应当用 LaTeX 文本定界。**

| 方案 | 可行性 | 理由 |
|---|---|---|
| 新增 `<\|formula\|>` 之类 special token | **不可行** | 需改 `vocab_size`、扩 embedding 并重新训练该行向量；而 **LoRA 默认不动 embedding**，新 token 等于随机噪声；还会破坏与官方 tokenizer 的兼容 |
| 自造 `<formula>` 普通文本标记 | 可接受，但有代价 | 实测 `<answer>` = 3 个 token（`<`+`answer`+`>`），是普通文本；模型能学，但要额外样本 |
| **LaTeX 定界 `$…$` / `$$…$$`** | ✅ **推荐** | 实测 `$$` 是**一个** token（14085）；模型原生就会用；sympy / latex2sympy 可解析，便于符号化判分 |
| 已有原子 token `<think>` / `</think>` | 可用 | 词表里现成的、唯一的"语义空位"（见 §5.8） |

**规范**：公式一律 LaTeX，块级 `$$…$$`、行内 `$…$`；
**禁止**在数据里自造 `<|...|>` 形式的标记——会与真特殊 token 视觉混淆，
且容易踩 tokenizer `split_special_tokens` 的坑。

### 5.8 CoT（思维链）：实测结论与决策

| 检验 | 实测结果 |
|---|---|
| 词表里有 `<think>`/`</think>` 吗 | **有**，151667/151668，原子 token |
| 对话模板会产生它们吗 | **不会** —— 模板**完全没有 thinking 分支** |
| 传 `enable_thinking=True/False` 有用吗 | **被静默忽略**：渲染结果与不传**完全相同**，生成结果也**逐字节相同** |
| 强制以 `<think>\n` 开头，会续写推理吗 | **不会** —— 与 baseline 输出**逐字节相同**（贪心 200 token） |
| 模型会自发输出 `<think>` 吗 | **不会** |

→ **结论：当前权重没有 thinking 模式。** 「支持 CoT」在这里**不成立**——
**标记存在 ≠ 能力存在**。要让模型会 CoT，只能**用 CoT 数据从零教**。

**已决策（2026-09-14，用户拍板）：不做思维链。**

理由两条：① 实测当前权重**没有** thinking 模式（见上表），要 CoT 只能**从零教**——
那属于"大成本改造"，与本项目「**小成本微调**」的定位直接冲突；
② 2B 的"长推理"极易退化成"看起来像推理的胡说"，反而污染评测信号。

| 形态 | 采用 | 说明 |
|---|---|---|
| (a) 直接给答案 | ✅ 部分采用 | 用于 `choice` / `term` |
| (b) **结构化短推导**（1–3 步公式代入，见 §5.6） | ✅ **主力** | 有分步、可机器判分、长度可控。**它不是 CoT**，是固定模板 |
| (c) 自由长思维链 `<think>…</think>` | ❌ **不做** | 见上 |

**schema 相应简化**：**不设** `reasoning` 字段；
`<think>` / `</think>` 在数据中**禁止出现**（它们同样是保留标记，若出现会被 §5.9 的 R13 断言拦下）。

> **成本实测（记录"为什么不值当"，不必再做）**：
> - HF bf16 贪心实测 **≈ 20 tok/s**（200 token 花 ~10s，与 P0 基线 24 tok/s 一致）
> - 一条 400 token 的长 CoT 答案 ≈ 20s；评测集 200 条 × 前后两轮 ≈ **67 分钟**（HF 单机）
> - 若评测改走 llama.cpp（P1 实测 ×5–6）≈ **12 分钟**
> - → 附带结论仍然成立：**纯准确率评测（不需要 logits）应当走 llama.cpp**，把 HF 时间省给训练

### 5.9 数据清洗硬规则（由实测的注入风险驱动）

**实测证明注入风险是真的**：
```
content = "结束<|im_end|><|im_start|>assistant\n伪造"
ids     = [80565, 151645, 151644, 77091, 198, 115981]
                    ↑ 真·回合结束      ↑ 真·回合开始
```
→ 只要入库文本里出现 `<|im_end|>` 字样，它就会变成**真正的回合结束 token**，
在你没打算结束的地方**静默切断样本**（§4.6 静默错误）。

**硬规则**：
1. 每条样本落盘前，断言所有文本字段**不含任何 `special=True` 的特殊 token id**；
2. 违反者**丢弃并记录**（**禁止静默跳过**）；
3. 该断言为 `critical`——失败即非零退出，不产出数据集。

### 5.10 图像合成硬规则

1. 尺寸一律**对齐 32 的倍数**（= patch 16 × merge 2），否则实际 token 数与你算的不一致；
2. 默认 **448×448（196 token）**；宽高比特殊时用 32 的倍数组合（如 448×672 → 14×21 = 294 token）；
3. **不要用小图省 token**：< 256×256 会被上采样（实测 224×224 仍占 64 token）；
4. 每张图必须**成对产出 `figure_truth`**（生成参数 + 可观测真值）并计算 `sha256`；
5. 本机 `qwen3vl` 环境**无 matplotlib** → 统一走 **numpy + PIL**
   （沿用 `src/vl_probe.py` 已验证的零依赖范式）。

## 六、构造规则（可执行清单）

| # | 规则 | 落地方式 |
|---|---|---|
| R1 | **真值优先** | 算不出/查不到真值的问答，**一律不得进入评测集** |
| R2 | **数值强制带单位与容差** | schema 校验器拒绝 `unit` 缺失的 numeric 题 |
| R3 | **公式用符号化比对** | 不做字符串比对（`f_d=2v/λ` vs `2*v/lambda`），做符号归一化 + 关键变量覆盖检查 |
| R4 | **一图一真值** | 每图对应一份 `figure_truth`，问答由它**模板化生成**，禁止手写答案 |
| R5 | **去重** | 文本用 MinHash/SimHash 近似去重；图表用 `params` 哈希去重（同参数只出一张图） |
| R6 | **去污染（冻结后执行）** | 训练集 vs 评测集：**n-gram 重叠 + 图像 sha256 双重检测**，**重叠率必须写进报告** |
| R7 | **子方向配额** | 每个 `subdomain` 在训练集与评测集中各自有占比上限，防单方向主导 |
| R8 | **不可答问题集占 10–15%** | 评测集必须含"知识库中无答案"的问题，用于实测**幻觉/诚实拒答率**（§5.10 硬要求） |
| R9 | **视觉 token 预算** | 实测 **196 视觉 token / 图 @448×448**（(448/16/2)²）；多图题需计入 `max_seq_len` 预算 |
| R10 | **拒答话术统一** | 规定唯一标准拒答句式，否则"拒答率"无法统计 |
| R11 | **云端生成必须本地复核** | **云端 LLM 产出的任何数值/公式答案，必须用本地程序重算一遍**，不一致即丢弃。此为 R1 的直接落实 |
| R12 | **固定随机种子 + 可复现** | 所有生成脚本固定 seed，产出可逐字节复现（§4.3） |
| R13 | **注入清洗（`critical` 断言）** | 落盘前断言文本字段**不含任何 `special=True` 的 token id**；实测 `<\|im_end\|>` 会真的切断样本（§5.9）。**禁止静默跳过**，违反即丢弃并记录 |
| R14 | **图像尺寸对齐 32 的倍数** | 否则实际视觉 token 数与预算不符（§5.10）；默认 448×448 = 196 token |
| R15 | **答案模板统一** | 每类任务一套固定模板（§5.6）；判分器与训练信号都依赖它，不得逐条自由发挥 |
| R16 | **禁止自造 `<\|...\|>` 标记** | 与真特殊 token 视觉混淆，且踩 `split_special_tokens` 坑；公式用 LaTeX（§5.7） |

### 9.0 依赖矩阵：哪些步骤需要语料、哪些**完全不需要**（先看这个）

## 十一、面试延伸

**Q1. 为什么评测集必须先于微调冻结？**
- 骨架：① 数据泄漏（训练时看到测试分布）→ 指标虚高；② 人的调参是隐性的——你会按评测集结果反推数据配比；③ 只有"先冻结、后训练"才能声称泛化。
- 追问方向："如果评测集确实不够好怎么办？" → 答：**新建一个 V2 评测集**并同时报告两版，而不是回头改 V1。
- 加分：本项目用**双重去污染**（文本 n-gram + 图像 sha256），因为多模态数据存在"文本不重叠但图相同"的隐蔽泄漏。

**Q2. 多模态数据集为什么要把文本与图表样本隔离训练？**
- 骨架：归因需要（§5.9 只改一个变量）；混合训练后无法区分提升来自语言先验还是视觉通路。
- 追问："那多模态不是应该联合训练吗？" → 答：工业界确实联合训练，但**本项目的目标包含"讲清每个变量的作用"**，所以先做受控对照，再谈联合。
- 加分：指向 P0 实测——视觉塔占 19.1%（406.9M），冻结它才能把显存留给语言侧 LoRA。

**Q3. 合成数据（synthetic data）怎么保证质量？**
- 骨架：① 真值必须**独立于生成过程**可验证（本项目的图形与真值同源但由公式独立计算）；② 生成器固定种子保证可复现；③ 云端生成的答案**必须本地复核**；④ 用去重与配额防止分布坍缩。
- 追问："合成数据的最大风险是什么？" → 答：**分布坍缩**（模型只学会生成器的语气与模板），以及**真值错误被批量复制**——一条错模板会污染成千上万条。
- 加分：说明为什么 L1 优于"纯云端生成"——L1 的真值是算出来的，云端是"说的"。

**Q4. 雷达数值题判分为什么必须带单位与容差？**
- 骨架：① 量纲是物理正确性的必要条件，单位错=答案错；② 浮点与近似公式（如 c 取 3e8）导致必须给容差；③ 单位混用（km/m、Hz/kHz、dB/线性）是雷达题最高频的错误来源。
- 追问："容差怎么定？" → 答：按**误差来源**定——常数近似（如 g=9.8 vs 9.81）给 1%，公式本身是近似的（如 3dB 波束宽度 0.88λ/D）给 5–10%，实测值给更大。
- 加分：指出"容差定得太松"会让错误的单位换算也被判对，所以容差本身要有依据、要写进报告。

**Q5. 怎么判断一个模型"支不支持"思维链（CoT）？**
- 骨架（四步，缺一不可，本项目全部实测过）：
  ① **看词表** —— CoT 标记是否存在（本项目 `<think>`/`</think>` = 原子 token 151667/151668）；
  ② **看对话模板** —— 模板会不会产生它（本项目模板**完全没有 thinking 分支**）；
  ③ **看模型行为** —— 强制加 `<think>` 前缀后输出有没有变化（本项目**逐字节不变**）；
  ④ **看开关** —— `enable_thinking` 之类参数是否真被消费（本项目**被静默忽略**）。
- 追问方向："那这个模型到底能不能学会 CoT？" → 答：**能，但那是从零教**，
  需要大量 CoT 样本去建立该行为，而不是"解锁"一个已存在的能力。**标记存在 ≠ 能力存在。**
- 加分：点出真正的坑是 **"参数被静默接受"** —— `apply_chat_template(enable_thinking=False)`
  既不报错也不生效（Jinja 未定义变量不报错）。凡是"传了个开关却没验证效果"的地方，
  都是静默错误的高发区；正确做法是**断言渲染结果发生了变化**。

## 十二、作者格式与框架用法（S1 已交付）

### 12.1 框架由四个文件组成

| 文件 | 职责 | 一句话 |
|---|---|---|
| `configs/dataset.yaml` | **spec**：阈值、模板、常量、任务定义的**唯一来源** | 改这里 = 改校验行为 |
| `src/dataset/formulas.py` | **公式注册表**：12 条信号处理基础公式 + 真值计算 | 答案由程序算，人写不了 |
| `src/dataset/schema.py` | **校验器**：结构 / 注入 / 单位 / 容差 / 图像 / 预算，`critical`-`warning` 分级 | 只做机器可判定的事 |
| `src/dataset/compile.py` | **编译流水线**：作者格式 → 校验 → 算真值 → 填模板 → 拼 `messages` → JSONL + sha256 | 产出可训练的数据块 |

入口：`scripts/p3_dataset_build.py`（`--check` / `--compile` / `--selftest` / `--formulas`）

### 12.2 你要做的事：用人类的语言写 `question`

```yaml
- id: txt_000001            # 前缀由 split×modality 决定，见 spec 的 id_prefix
  split: train              # train | eval
  modality: text            # text | vision
  task: calc                # calc | formula | choice | concept | term | unanswerable
  subdomain: resolution     # 用于分层统计与配额
  difficulty: easy
  question: >-              # ← 你写的就是这一句，人类语言
    某雷达发射线性调频信号，带宽 B = 10 MHz。已知光速 c = 3×10^8 m/s，
    求该雷达的距离分辨率 ΔR。
  formula: range_resolution # ← 指定公式
  inputs: {B: 1.0e7}        # ← 只给物理量（SI 单位）
  unit: m                   # ← 期望输出单位，必须与公式一致
  tol_rel: 0.01
```

**你不需要写答案**。框架算出 `ΔR = 15 m`，并按固定模板生成 assistant 内容：

```
公式：\Delta R = \frac{c}{2B}
代入：\Delta R = \frac{3\times10^{8}}{2 \times 1\times10^{7}} = 15\ \text{m}
最终答案：15 m
```

→ 于是**答案与题面天然自洽**，且 `answer_check` 自带数值 + 单位 + 容差，可直接机器判分。
这正是"人写问法、机器写答案"的分工：**人最擅长措辞，机器最不会算错**。

对于 `choice` / `concept` / `term` / `formula` / `unanswerable`，答案由你写，框架只校验格式、
长度、注入与拒答句式（这类题的语义正确性只能靠人 / 后续裁判 LLM）。

### 12.4 ⚠️ 校验器的职责边界（**别指望它做它做不到的事**）

| 能拦住（机器可判定） | **拦不住**（必须人 / 裁判 LLM 把关） |
|---|---|
| 字段缺失、类型错、枚举越界 | **公式用得对不对**（题目问分辨率却选了模糊函数） |
| 特殊 token 注入（会切断样本） | **概念解释是否符合雷达专业共识** |
| 单位不匹配、容差非法 | 题面表述是否清晰、无歧义 |
| 选择题答案不在选项里 | 题面里提到的量是否真被公式用到 |
| 图像尺寸未对齐、缺 sha256 / 真值 | 图像的**内容**是否正确渲染 |
| token 超预算、子方向配额失衡 | 与语料的一致性（需 L2 到位后抽查） |

> **一句话**：校验器保证"**数据是规范的、答案是可算的**"，

## 十三、体制维度与术语口径（回答"不同雷达体制怎么规范"）

> 起因（2026-09-15）：用户提出「雷达体制不一样，对同一内容的描述也会有差别，
> 比如车载毫米波、机载脉冲、地基脉冲、MIMO……问答中是否需要规范，
> 还是需要更硬性的设置？」

### 13.1 结论

**需要规范，但不是"把题面写硬"，而是把「体制」提升为 schema 的一等字段，
并配一张术语口径表。** 三件事同时做：

1. **加 `regime` 字段**（必填）—— 与 `subdomain` **正交**；
2. **题面必须显式声明体制** —— 这一条**可机器判定**，因此可写成 critical 断言；
3. **加术语口径表 `term_registry`** —— 记录同一术语在不同体制下的口径差异与常见错法。

### 13.2 为什么必须做（三条理由，都不是"为了整齐"）

| 理由 | 说明 |
|---|---|
| **① 没有唯一答案** | 「距离分辨率」在脉冲雷达里 B 是信号带宽，在 FMCW 里 B 是**扫频带宽**，在 SAR 方位向则**与带宽无关**（ΔR_az = D/2）。不声明体制，这道题就没有唯一真值，也就**无法机器判分** |
| **② 无法归因** | 数据集里混着多个体制时，"微调带来了什么提升"说不清来自哪个体制（§5.9 只改一个变量） |
| **③ 无法测幻觉** | 模型极易把车载毫米波的结论套到机载脉冲雷达上。不显式标注体制，就**造不出针对性的检测题** |

> 注意你举的两个例子——「机载雷达回波如何建模」「毫米波雷达如何进行测角」——
> **恰好都是体制强相关的**。这不是巧合：**回波建模、测角、分辨率**正是体制差异最集中的三处。

### 13.3 机制一：`regime` 字段（必填，正交于 subdomain）

```
subdomain = 问的是什么知识（脉压 / 模糊 / 分辨率 / 雷达方程 / 多普勒 / 其他）
regime    = 在哪个体制下问（universal / 地基脉冲 / 机载脉冲 / 星载 / 车载毫米波 / FMCW / MIMO / SAR / 相控阵）
```

`universal` = 体制无关的**普适原理**（雷达方程、匹配滤波、多普勒、模糊函数），此类不需要体制限定，答案唯一。

**关键规则（可机器判定）**：`regime != universal` 时，题面**必须**出现该体制的"表面词"
（在 `configs/dataset.yaml` 的 `regimes.<名>.surface_terms` 里定义）。
否则报 `E_REGIME_SURFACE`（critical）—— 因为它让读者无从判断在问哪个体制。

反向也有：`regime=universal` 却在题面写了"毫米波"，报 `W_REGIME_MISMATCH`（warning）。

> 这条规则在交付时**立刻抓到了我自己犯的一个错**：夹具里 `txt_000008` 写的是
> 「某型未公开的舰载**相控阵**雷达…」却标了 `universal`。规则报出后已改为 `phased_array`。

### 13.4 机制二：题目形态分三档，V0 只用「硬 + 半硬」

这是对你"是否需要更硬性的设置"的直接回答：**不是二选一，而是三档，按可判分性取舍。**

| 档 | 形态 | 可判分性 | V0 |
|---|---|---|---|
| **硬**（closed） | 数值题 / 选择题 / 判断题 | ★★★ 全自动 | ✅ 主力 |
| **半硬**（semi） | 简答，但**要求答出指定要点**（要点集进 `answer_check`） | ★★ 关键词覆盖自动 + 人工抽检 | ✅ 采用 |
| **软**（open） | 自由论述 | ★ 只能 LLM 裁判（D4 未决） | ❌ **V0 不收** |

**你举的两个例子属于「软」，V0 需要改造成「半硬」**：

| 原标题（软） | V0 改写（半硬，可判分） |
|---|---|
| 机载雷达回波如何建模？ | 简述**机载**脉冲雷达回波建模中，平台运动主要引入哪**两类**效应。<br>→ 要点集 `{距离走动, 多普勒走动/展宽}` |
| 毫米波雷达如何进行测角？ | **车载毫米波**（FMCW）雷达工程上主流的测角方法是什么？<br>→ 直接改成 `choice` / `regime_trap`，答案唯一 |

改写的判据很简单：**把"如何/怎么"换成一个有界的问题**（问几个、问哪一个、问属于哪一类）。
这样既保留自然语言的问法，又拿得到唯一真值。

### 13.5 机制三：新增题型 `regime_trap`（专测"体制串味"）

选择题的变体：**选项里故意放入其他体制的答案**。它直接回答"模型会不会把 A 体制的结论套到 B 体制"。

已落地示例（`txt_000010`，答案 B）：

> 某**车载毫米波**雷达工作于 77 GHz、采用 **FMCW** 体制，需要估计前方目标的角度。下列哪种方法是该体制下的工程主流做法？
> A: 单脉冲和差波束测角　B: MIMO 虚拟阵列 + 角度 FFT　C: 机械扫描顺序波瓣法　D: 圆锥扫描测角

A/C/D 都是**真实存在但在该体制下不是主流**的做法 —— 这就是陷阱。
这类题在面试里也是加分项（能讲清"为什么是 B 不是 A"）。

### 13.6 机制四：术语口径表 `term_registry`

文件：`src/dataset/term_registry.py`。每条术语记录：

- `universal`：普适口径
- `by_regime`：各体制下的口径差异（含公式）
- `confusable`：**最常见的错法** ← 直接用来出 `regime_trap` 题
- `verified`：是否已与教材交叉核对

已有 6 条骨架：`range_resolution` · `angular_resolution` · `angle_measurement` ·
`echo_model` · `doppler_frequency` · `unambiguous_range`。

> ⚠️ **数据等级：目前全部 `verified: false`**（通行口径，但**尚未与教材交叉核对**）。
> 按 §9.0 纪律，`term_key` 挂到 **评测集**上会直接报 `E_TERM_UNVERIFIED`（critical）——
> 即"未核对的术语口径不得进入评测集"。L2 语料到位后逐条核对，改 `verified: true` 即可解锁。

**举例：为什么这张表是必要的**

| 术语 | 普适 | FMCW / 车载 | SAR |
|---|---|---|---|
| 距离分辨率 | ΔR = c/2B | 同式，但 **B 是扫频带宽** | **方位向 ΔR_az = D/2**，与带宽无关 |
| 最大不模糊距离 | R_u = c/(2·PRF) | **连续波体制没有这个概念** | — |
| 测角主流 | 相位比较 / 波束形成 / 超分辨 | 虚拟阵列 + **角度 FFT** | 方位靠合成孔径成像，非逐脉冲测角 |

若没有这张表，上述三行会被写成同一个答案 —— 那就是**静默错误**。

### 13.7 成本提醒：V0 别铺开

体制维度会让样本需求**组合爆炸**。框架已内置两条配额警告：

- `W_REGIME_SPREAD`：`universal` 占比 < 30% 时告警（体制题太多 → 无法归因）
- `W_REGIME_TOO_MANY`：涉及 **> 3 个具体体制**时告警

**V0 建议**：`universal` 占 60% 以上；具体体制只挑 **2–3 个差距最大的**
（如 `airborne_pulse` vs `automotive_mmwave` vs `sar`）——差距大才值得做，差距小只是换个词。

> 当前夹具 `sp_basics_v0.yaml` 用了 4 个具体体制，**框架正确地报了 `W_REGIME_TOO_MANY`**。
> 这正是它该有的行为：不是拦你，是提醒你别把预算铺散。

### 13.10 `keypoints` 要点集（2026-09-15 用户拍板"现在加"）

**解决的问题**：`docs/05 §13.4` 把题目分三档，其中「半硬」（简答但要答出指定要点）此前**没有字段承载要点**，
于是 `concept` / `contrast` 只能做 `keyword` 全串匹配 —— 判分器形同虚设。

**落地**：

| 位置 | 改动 |
|---|---|
| `configs/dataset.yaml` | `concept.required: [answer, keypoints]`，`keypoints: {min: 2, max: 6}`；`contrast` 同理但 `min: 3`（对比题要分别答到两个体制） |
| `src/dataset/schema.py` | 新增 4 条断言：`E_KEYPOINTS`（缺失/非字符串列表）· `E_KEYPOINTS_COUNT`（越界）· `E_KEYPOINTS_DUP`（重复）· **`E_KEYPOINT_NOT_IN_ANSWER`** |
| `src/dataset/compile.py` | `answer_check` 带上 `keypoints`，判分器可按"要点覆盖率"给分 |
| 反例夹具 | 新增 4 条，**全部命中**；反例规模 28 → **32 条**，命中 critical 24 → **28 条** |

⭐ **最要紧的一条断言是 `E_KEYPOINT_NOT_IN_ANSWER`**：要求**每个要点都是 `answer` 的子串**。
理由：若某个要点在参考答案里都不出现，判分器将对**任何**输出都判不过 ——
准确率恒为 0，但流程一声不响（**静默失效**）。这正是本项目要提前用断言堵住的那类错误。
> 对照 `docs/05 §5.6`：`keypoints` 只用于"半硬题"；`calc` 仍走 `numeric`（数值+单位+容差），
> **两类不混用同一套判分器**。

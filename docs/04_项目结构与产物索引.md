## 二、加新文件时该放哪（决策表）

| 你要加的东西 | 放哪 | 判断依据 |
|---|---|---|
| 一个新的超参 | `configs/base.yaml`（共享）或 `configs/engines/<引擎>.yaml`（引擎专有） | **同一参数只在一处定义** |
| 一次实验的变量组合 | `configs/bench/*.yaml` 的 `overrides` | 矩阵只引用引擎名，不重复引擎参数 |
| 可复用的逻辑 | `src/` | 无副作用，可被多处调用 |
| 一个新引擎 | `src/engines/<name>_engine.py` + `configs/engines/<name>.yaml` | 引擎名 = yaml 文件名 = 适配器 `name` 属性，三者必须一致（有断言） |
| 一个可执行入口 | `scripts/` | 只做参数解析与编排，业务逻辑回 `src/` |
| 一个阶段的报告 | `docs/0N_<阶段>.md` | 五段式（Why/原理/代码/验收/面试延伸） |
| 数据集 schema / 校验器 / 编译 | `src/dataset/{schema,formulas,compile}.py` + 入口 `scripts/p3_dataset_build.py` | 同「src vs scripts」分层铁律 |
| 数据集阈值与答案模板 | `configs/dataset.yaml` | **同一参数只在一处定义** |
| 人写的问答源文件 | `data_authored/*.yaml` | 是**输入**，不是可重建产物；带版本号如 `sp_basics_v0.yaml` |
| 数据集本体 | `data_processed/datasets/*.jsonl` + `.manifest.json`；图 `data_processed/figs/` | 可重建；**EVAL 冻结必须记 sha256** |
| 数据集方案 / 决策 | `docs/05_雷达问答数据集方案.md` | 跨阶段设计文档（P2 语料 × P3 数据构造） |
| 一次实验的**原始产物** | `outputs/<exp>_<时间戳>/` | 脚本自动生成，不要手建 |
| 面向人的结论/图表/评测集 | `reports/` | 从 `outputs/` 里挑最终那一轮提升上来 |
| 安装/服务/探测的原始日志 | `logs/<install\|server\|probe\|bench>/` | 用 `p1_organize.py --apply` 自动归类 |

## 三、证据保全策略（**最重要的一节**）

### 3.0 ⭐ 指纹（sha256）的规矩 —— 只留给该留的（2026-09-15 用户反馈后清理）

> 起因：用户问"**哈希用来干嘛的？能别搞这些复杂的东西吗？**"
> 我逐处 grep 了「谁在读」，结果**大部分是只写不读**：`meta.compiled_at`（全项目零读取）、
> `book_sections.jsonl` 每节的 `sha256`、`_merge_manifest.json` 里各产物的 `sha256`、
> mmWave 仓库的 61 条逐文件 `sha256`（与 `.git` 的 HEAD **重复劳动**）。已全部删除。

**哈希只回答一个问题：「现在这份东西，还是当初那一份吗？」** 它不是安全/密码学那套，
就是**指纹比对**。所以判据是两条，满足其一才留：

| 留的条件 | 本项目的例子 | 为什么 |
|---|---|---|
| ① **必须证明身份**（答案/结论依赖它） | 题目里的教材图 `image.sha256` | 重跑解析器后图片像素可能变，而题目还写着"图2.4.4(u)，答案 t_p=2μs" → 没有哈希**不会被发现**，错答案一直用。框架对此有 critical 断言（`E_IMG_NO_SHA256` / `E_IMG_SHA256_MISMATCH`） |
| ② **重造代价高** | MinerU 分片产物（各片 `_shard.json`） | 全量重跑约 30 分钟，且版本一变换了结果说不清；留指纹让"是不是同一批解析产物"可查 |

**不留的**：能由分片/源文件**一条命令重算**的 jsonl / md（如 `book_sections.jsonl`、
`book_full.md`、合并清单里的产物）—— 留指纹没有消费者，只增加噪音。

**两条配套纪律（都是踩过的）**：

1. ⚠️ **产物哈希要可复现**：编译产物里**禁止嵌入时间戳**。
   原来 `meta.compiled_at` 让"同样输入 → 不同字节"，于是"冻结评测集时用 sha256 当身份"**根本不成立**。
   删掉它之后实测：同一份 YAML 连编两次，`sha256` **完全一致**（需要时间看 manifest 的 `written_at`）。
2. ⚠️ **删字段要查消费者**：删掉 `book_sections.jsonl` 的 `sha256` 后，
   `p2_render_corpus_review.py` 里那行读取立刻 `KeyError` —— 删字段和改断言一样，
   都要回头确认"谁在依赖它"。


### 3.1 为什么不能随手删

规范 §5.2 **禁止编造指标** —— 报告里每个数字都要能回溯到一份原始日志。
所以"清理冗余文件"与"保住证据"是一对矛盾，本项目用**机器可判定的规则**来解：

> **凡被 `docs/*.md` 或 `reports/*` 引用的 `outputs/<run>` / `logs/<file>`，一律保留。**

`scripts/p1_organize.py` 每次运行都会自动做这个扫描（正则提取引用名），
并把它标记为 `KEEP(cited)`；**即使某个路径同时出现在删除白名单里，也会被跳过**。

### 2.5 ⭐ 教材自身不自洽的一处（实测核验，用户要求取证）

起因：`docs/05` 的 `txt_000106` 涉及"RCS 与作用距离"的关系，我怀疑教材有一处近似。用户要求
「**把相关内容找出来，我看看教材是如何表述的**」→ 于是全文搜了 `4次方根 / 1/10 / 50% / 雷达截面积`。

**教材原文（第1章 1.4.2「雷达的四大威胁」→ 3. 隐身与反隐身技术，PDF p42）**：

> 根据雷达方程，雷达发现目标的距离与雷达反射截面积的 **4 次方根**成正比。在其他参数不变的情况下，
> 当目标的雷达反射截面积减小到原来的 **1/10** 时，雷达的作用距离将缩短为原来的 **50%**。

**同一段里教材还给了另外两个例子。三个都算一遍**（核验脚本 `scripts/p2_radar_equation_evidence.py`，
输出 `logs/probe/p2_radar_equation_evidence.txt`）：

| # | 教材表述 | 按 4 次方根算 | 是否自洽 |
|---|---|---|---|
| ① | RCS 减到 **1/10** → 距离缩短为原来的 **50%** | (1/10)^(1/4) = **56.2%** | ✗ **差 6.2 个百分点** |
| ② | B1-B 的 RCS 是 B-52 的 **3%** → 探测距离下降 **58%** | 3% → 距离剩 41.6% → 降 **58.4%** | ✓ 吻合 |
| ③ | F-117A/B-2 的 RCS 降 **20~30 dB** → 距离降为 **1/3~1/6** | 1/3.16 ~ 1/5.62 | ✓ 吻合 |

**结论**：三例中**两例精确吻合**，只有 ① 不符 → 判定为**笔误或口语化近似**，
**不是**教材采用了另一种约定。补一个数：若要得到正好 50%，RCS 应为 **1/16**（0.5⁴ = 0.0625），
所以 ① 那句里 `1/10` 与 `50%` 至少有一个写错了。

**处置（用户拍板：用精确值）**：`txt_000106` 的答案取 **56%**，
并在 `notes` 里并列教材原话与三个例子的核验结果（**保留冲突、写清理由**，而不是掩盖）。
另一处对照（第5章 5.1.3，PDF p178）表述正确，可直接引用：

> 雷达最大作用距离和发射机功率的 4 次方根成正比；雷达最大作用距离正比于目标雷达截面积（RCS）的 4 次方根。

> 📌 **这一条的普遍意义**：教材进入 `evidence.quote` 之前必须**过一遍算术**。
> 本项目对云端 LLM 的产物有 R11「必须本地程序复核」，**对教材同样适用**——
> 出处权威 ≠ 数值正确。这是 §七「教材本身有近似/笔误」风险的具体实例。

### 3.1 决策记录：**我推荐 A，用户拍板 B**（分歧如实记录）

**我当时的推荐理由（不撤回，供以后复查）**：

1. 本项目**数值真值由公式注册表程序算**，教材只提供术语口径与证据句，
   而**证据句所在的散文段落，pymupdf 抽得是干净的**（§2.2 已实测）→ 公式抽取质量差不构成阻塞；
2. 公式的正确性由**人看着 PDF 写 LaTeX** 保证（`docs/05 §5.7`），比"抽出来再清洗"更可靠；
3. 我担心的是成本：**1.5–3 GB 下载 + 全量解析耗时**。

**用户拍板 B 的理由（我接受，且它推翻了我的第 3 条）**：

1. **要做 SFT-V，教材图要进数据** ——「**理解架构图也是一部分**」。
   这是 A **根本做不到**的能力：pymupdf 只能导出整页位图，**没有图注绑定、没有版面结构、没有图的语义**；
   而 MinerU 自带 `--image-analysis`（VLM 图像/图表理解），正好对上这个需求。
2. 后续要**判断模型对教材图的理解是否正确**，图与图注必须**成对结构化产出**，
   再由**人工核对**给出真值 → 这决定了图像抽取必须是"结构化的"，而不是"截个图"。

**⚠️ 我的成本判断被实测修正两次 —— 第二次是我自己错了，必须记下来**：

**第一次（对的方向）**：我一度准备建议"另建独立 env"，理由是 MinerU 可能把 `transformers` 从 **5.17.0** 降级。
但 `pip install mineru`（**基础包**）的 dry-run 显示：**只新增 50 个包、零个包被变更**。
→ 我据此在文档里写了"**没有环境破坏风险**"。**这个结论是错的**（见下），只是因为证据不完整。

**第二次（我错了，实测推翻第一次）**：装完之后真正去跑，MinerU 直接报
`HybridDependencyError: \`hybrid-transformers\` requires local pipeline dependencies (mineru[pipeline])` ——
**基础包根本跑不起来**。补装 extras 的 dry-run 实测（`logs/install/p2_mineru_{vlm,pipeline,core}_dryrun.json`）：

| extras | 是否可运行 | `transformers` | `tokenizers` | `huggingface_hub` |
|---|---|---|---|---|
| （基础包，已装） | ❌ **不可运行** | 不动 | 不动 | 不动 |
| `mineru[vlm]` | ✅ | **5.17.0 → 4.57.6** ⚠️ | 0.23.2 → 0.22.2 ⚠️ | 1.31.0 → 0.36.2 ⚠️ |
| `mineru[pipeline]` | ✅ | **5.17.0 → 4.57.6** ⚠️ | 0.23.2 → 0.22.2 ⚠️ | 1.31.0 → 0.36.2 ⚠️ |
| `mineru[core]` | ✅ | **5.17.0 → 4.57.6** ⚠️ | 0.23.2 → 0.22.2 ⚠️ | 1.31.0 → 0.36.2 ⚠️ |

→ **"能跑"与"零变更"不可兼得**：只要装 extras 跑 MinerU，`transformers` 就从 5.17 掉到 4.57，
连带 `tokenizers`/`huggingface_hub`。而 **P0/P1/P3 的全部结论都是在 `transformers 5.17.0` 上测的**
（`apply_chat_template`、`Qwen3VLProcessor`、特殊 token 表），**降级会让这些结论的环境前提失效**。

> ⚠️ **教训（我的错，写下来）**：我把"**基础包** dry-run 零变更"当成了"**这个工具**环境无风险"的证据。
> 证据范围不匹配结论范围 —— **一个跑不起来的包，它的依赖报告不能证明任何事**。
> 正确做法：dry-run 必须针对**真正要用的那组 extras**。
> （这与 SOUL.md「结论先声明证据等级」是同一条：**未验证 ≠ 已验证**。）

**因此：MinerU 的执行方式成了一个必须由用户拍板的新决策点**（见 §3.4）。

```json
            "image_caption":[{"type":"text","content":"图2.4.3 矩形脉冲的模糊函数图"}]},
 "bbox":[147,107,550,340]}
```
→ **这是 SFT-V 的素材基础**（用户 D-P2-3 要的"判断模型对教材图的理解"）。
另外它把**曲线图单独判成 `chart`**（与示意 `image` 分开），多行图注（含子图标注 `(u)`/`(b)`）也带上了。

**⚠️ 但 MinerU 会犯"看起来对"的错 —— 这条必须记牢**：
实测 p78「模糊函数唯一性定理」处，MinerU 输出

> 则当且仅当 $u_1(t) = c\,u_1(t)$ 且 $|c| = 1$ 时 …

**语法完全合法的 LaTeX，但语义是错的**：唯一性定理要求的是 $u_2(t)=c\,u_1(t)$
（前文刚说了"信号 $u_1(t)$ 和 $u_2(t)$"）。这是**下标识别错误**，
而它**看起来完美**——不核对绝对发现不了。

→ 结论：**公式的 LaTeX 不得直接从解析结果抄进数据集**，
必须按 `docs/05 §5.7` 的既有规定**由人核对/手写**。
这也说明"解析质量高"与"数据可用"是两件事：**前者是概率，后者要证据**。

**因此 A 方案（pymupdf）不废弃**：降级为**零依赖兜底 + 双信源比对**
（某页可疑时用它抽同一页交叉核对，正是 §5.8 的用法）。

2. ⚠️ **md 不以页为单位**：实测切片 md 可能直接以 `$$` 公式开头，无法按页切。

3. 合并时逐片断言页数、全局查重页号；产出 `book_full.md` / `book_pages_v2.jsonl` /

**⭐ 分片到底会不会让抽取结果漂移？—— 做了一次免费的交叉验证**：

|---|---|---|---|
| 按 **MinerU 文件名**比 | **58/58 重合** | **0/50 重合** ⚠️ | — |

- ✅ **分片不改变抽取结果**：内容哈希 100% 重合。所以"分片"只损失跨片标题层级上下文，

## 附录 A（原 §3.1）：为什么"不做高保真公式抽取"曾是我的首选

> 保留此段作为**决策轨迹**，避免以后重开会话时无法复盘"当初为什么想过另一条路"。

本项目**不需要**高保真公式抽取，因为按 `docs/05` 的设计：
数值题的真值由公式注册表程序算出（`src/dataset/formulas.py`），教材只负责提供**术语规范**与**证据句**。
而实测证明：**证据句所在的散文段落抽得是干净的**。
公式的正确性则由**人看着 PDF 写 LaTeX** 保证（`docs/05 §5.7`：公式一律 LaTeX、禁止自造标记），
比"从 PDF 抽出来再清洗"更可靠——解析器会把 `[π( )]` 抽成什么，§2.2 已经看到了。

**这套推理仍然成立**，只是它**没有覆盖"教材图要进 SFT-V"这个新需求**。
→ 教训：**方案选型必须覆盖用户的实际目标，而不是只覆盖"最小可行链路"。**

## 四、抽取流水线设计（S1–S3）

### 4.0 ⭐ 依赖关系：**文本题不等全量解析**（先看这个，避免把两件事串成一串）

常见误解：「题都要等解析跑完才能出」。**不对。** 按题目类型拆开看：

| 题目类型 | 真值/答案从哪来 | 依赖全量解析？ | 现在能做吗 |
|---|---|---|---|
| `calc` 数值题 | **公式注册表程序算**（`src/dataset/formulas.py`） | ❌ **完全不需要** | ✅ **现在就能批量出** |
| `concept` / `term` / `choice` | 教材**散文段落**（人工写答案） | ⚠️ **部分**——散文用 pymupdf 已能抽干净（§2.2 实测） | ✅ 现在就能出；解析完成后可**系统化**化 |
| `formula` 公式题 | 教材公式的 LaTeX | ✅ 需要（且**仍须人工核对**，§3.4） | ⏳ 等解析 |
| `figure_qa` 等 **SFT-V** | 教材**图 + 图注** | ✅ **硬依赖**（图注绑定只在 MinerU 产出里） | ⏳ 等解析 |

**那全量解析对文本题的增益到底是什么？** 不是"能不能做"，而是**"能不能系统地做"**：

| 增益 | 说明 |
|---|---|
| **覆盖均衡** | 现在是我「关键词搜索 + 定向抽页」找证据（如 `p2_corpus_probe.py`），**靠我记得搜哪些词**；有 `book_sections.jsonl` 后可按 **201 条目录逐节过**，漏节一目了然 |
| **配额可统计** | 按 `subdomain` 做分布统计与配额控制（R7），而不是凭感觉 |
| **出处可规范化** | `evidence.source` 可写成「第2章 2.3.5（PDF p82）」这种**机器生成**的定位，而非手写 |
| **公式引用更可靠** | 概念题若引用教材原式，MinerU 的 LaTeX 质量高一截（但对照 §3.4，**仍不得直接抄**） |

> **所以正确的顺序是**：全量解析（后台跑着）→ 结构化切分 → **你评审那 10 条样例** → 按目录/配额**系统放量**。
> 不先放量的原因不是"不能"，而是**样例口径未定就放量会返工**（措辞、证据粒度、`keypoints` 粒度都可能要调）。
> 另见 `docs/05 §9.0` 的依赖矩阵：S2/S3 **本就不需要语料**。

### 4.1 数据流

```
知识库/*.pdf ──pymupdf──┐

mmWave_Insight/docs ────┘        │
   （Markdown 直读）              │

                                  └─► data_processed/corpus/figs/               （可选：导出教材图，供人工查阅）
                                                    │

                                                    ↓
                                      data_authored/p2_*.yaml
                                                    │  scripts/p3_dataset_build.py --compile
                                                    ↓

```

### 4.2 切分粒度（按目录三级，保留页码锚点）

每条语料落盘为一行 JSON，字段：

```json
{
  "id": "book_2.3.3",
  "chapter": "第2章 雷达信号基本理论",
  "section": "2.3 模糊函数",
  "subsection": "2.3.3 模糊函数的物理意义",
  "pdf_page_start": 79,
  "pdf_page_end": 80,
  "text": "…规范化后的正文…",
  "n_chars": 812,
  "has_formula_garbage": true,
  "sha256": "…"
}
```

- **页码锚点必须留**：`evidence.source` 里写的 "(PDF p82)" 就是靠它机器回溯的
  （注意：**PDF 页序 ≠ 书内印刷页码**，本方案统一用 PDF 页序，并在引用时标注）。
- `has_formula_garbage` 用启发式打标（连续短行比例、非常用符号密度），
  用于**人工抽检排序**——先看标红最多的那些节。

### 4.3 文本规范化（已知要有哪些处理）

| 现象（实测） | 处理 |
|---|---|
| 页眉 `第N章  xxx` 混入正文 | 正则剥除（`^第\s*\d+\s*章\s*\S+`） |
| 印刷页码单独成行 | 正则剥除（独占一行的 1–3 位数字） |
| 公式碎片与句子交错 | **不强行修复**；整节带 `has_formula_garbage` 标记，交人工 |
| 图注 `图2.4.7 xxx` | 保留（它是图与正文的锚点，也是将来图表题图注的来源） |
| 全角/半角空格混用 | 抽题时归一（本题的 YAML 一律**单行书写**，否则 YAML 折行会在中文里插空格） |

### 4.4 与现有框架的对接（**不需要改 schema**）

抽取产出的语料**不直接进数据集**，而是作为**人写题面的素材**。
人写 `data_authored/p2_*.yaml`，由 `scripts/p3_dataset_build.py --compile` 产出 JSONL——
这条链路 `docs/05 §十二` 已交付，本阶段**零改动**（只按下面 §4.5 修了三处缺陷）。

### 4.5 ⚠️ 本阶段在框架里发现并修掉的三个缺陷（**都属静默错误**）

| # | 缺陷 | 危害 | 处置 |
|---|---|---|---|
| 1 | `term_registry` 的 `verified` 挂在**术语**上 | 只要核对过任意一条口径，整个术语被放行 → **"换个体制就能绕过核对"** | 拆成 `Term.universal_verified` + `RegimeNote.verified`，判定精确到**本样本用到的那一层**（`schema.is_verified_for`） |
| 2 | `schema.py` 里 `E_TERM_UNVERIFIED` 写在 `elif` 链末端 | 一旦先报"该体制无口径"的 warning，后面的 critical **被吞掉** → 未核对的口径**静默进入评测集** | 两项检查拆成**独立**语句，互不遮蔽 |
| 3 | `compile.py` 里 `regime_trap` 落到 `keyword` 兜底判分 | 字母答案用"输出里搜到 B"来判 → **静默虚高**（测试还会全绿） | 与 `choice` 合并为精确匹配 |

> 附带影响：把 `range_resolution` 标为已核对后，自检夹具 `evt_100036` **再也打不响**（测试静默失效）。
> 已把该夹具改用仍未核对的 `angular_resolution`，断言覆盖不丢。
> —— 这本身是一个值得记下来的教训：**"修好了功能"可能悄悄使"守护它的测试"失效**。

#### ⭐ 我在做这个提案时**推翻了自己一个方案**（如实记录）

我一开始写了"合并后失去 symbolic 判分 → 给 **calc 配 keypoints** 把公式形式补回来"，
**验完自己撤掉了**，理由是实验性的：

- 计算题的答案模板只生成「公式 / 代入 / 最终答案」三行 → **没有位置放语义要点**；
- 若拿 LaTeX 当要点又极脆：`\frac{c}{2B}` 与 `c/(2B)` 是同一个式子，**字符串却不同** → 大量假阴性。

## 十、面试延伸

**Q1. 解析教材 PDF 时，你怎么决定"用不用重型解析器"？**
- 骨架：先**探测素材性质**（有无文字层、有无目录、公式密度），再按**下游真的需要什么**选工具。
  本项目下游只要"术语 + 证据句"，散文抽取就够 → 不装 1.5–3 GB 的版面分析模型。
- 追问："那公式怎么办？" → 答：数值真值由**程序算**（公式注册表），LaTeX 由**人写**，
  两条路都不依赖解析器。**把不确定性从工具转移到可验证的环节**。
- 加分：说明"**先探测后选型**"的价值——如果一开始按惯例认定"教材 PDF 能抽文本"就上工具，
  会在扫描版那份上白花几小时，且直到发现输出为空才发现。

**Q2. 为什么要给语料保留页码锚点？**
- 骨架：① 评测集要求 `evidence.quote` 可回溯（§5.2），页码是回溯的最短路径；
  ② 语料重新抽取/换版本后，能定位"哪一条变了"；③ 人工抽检时能直接翻页对照。
- 追问："PDF 页序和印刷页码不一致怎么办？" → 答：**统一口径并显式标注**，
  比"哪个都行"更安全——否则两个人都说 p82，指的却是不同内容（静默错误）。

**Q3. 你怎么知道一份语料"够不够用"？**
- 骨架：不看总字数，看**与子方向的同构度**。本项目 D6 选的是信号处理基础，
  而教材第 2/4/5 章正对应匹配滤波、模糊函数、脉压、雷达方程、多普勒；
  同时"机载"这一体制的独特性（距离走动、空时耦合、三种 PRF 模式）在第 3/4/7 章。
  → **"能覆盖目标知识点"比"体量大"重要**。
- 加分：指出反过来也成立——如果语料集中在 SAR 成像而 D6 只要脉压基础，
  那再多字也**不能**支撑评测集冻结（因为口径对不上）。

**Q4. 你在这一阶段修了什么 bug？为什么说它是静默的？**
- 骨架：三个，共同点是**都不报错**：
  ① 术语核对粒度太粗 → "换个体制"绕过核对；
  ② `elif` 链把 critical 吞掉 → 未核对的口径静默进评测集；
  ③ 字母答案用关键词判分 → 命中即判对，指标虚高。
- 追问："怎么发现这些的？" → 答：① 来自框架自己报的 `W_TERM_UNCOVERED`；
  ② 来自读代码时注意到 `elif` 的短路语义；③ 来自**把编译产物渲染成人类可读评审件**——
  看到 `answer_check.type` 是 `keyword` 而不是 `choice` 才发现的。
- 加分：说明"**生成一份给人看的中间产物**"本身就是一种测试手段——
  它让那些不会被断言拦住的问题**暴露给人眼**。

**Q5. 你怎么避免"拿小样本外推到全量"这类错误？**
- 骨架：本项目在同一个坑里栽了**三次**（严格说两次是同一个错）：
  ① 用 3 页小样算出 14.53 s/页 → 推全量 88 min，实际只需 12–18 min（**高估 7 倍**，
     因为把"固定模型加载"摊到了每一页）；
  ② 用 3 页小样得出"图注绑定率 100%"，全量实测 **85.6%**；
  ③ 用 3 页小样断言"分片不影响质量"，这次**结论侥幸对了**，但真正的证据是后来拿
     崩溃前的 845 张图与分片结果按**内容 sha256** 对撞（100% 重合）才拿到的。
- 追问："那正确做法是什么？" → 答：**先问"我测的这个量是常数还是平均值"。**
  常数（如模型加载）不能摊到分母；平均值要报**分布**而不是一个数
  （本项目分片耗时就横跨 30.9 s–276.9 s，任何"平均速度×页数"都是错的）。
  再就是**同一结论必须有范围匹配的证据**——这正好是 §5.2/§4.6 那两条规范想拦的东西。
- 加分：主动说出"我错在哪儿、怎么发现的"比说"我从不犯错"更有说服力——
  面试官真正想确认的是**你的产物有没有被校验过**。

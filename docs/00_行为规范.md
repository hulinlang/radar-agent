## 3. 输出结构规范（强制模板）

**后续每一个教学/实践环节，我都严格按以下五段式输出，段落标题固定，顺序固定。**

### 【① 这一步要解决什么】（Why）
1–3 句话说明：这是什么、在整条链路的哪个位置、不做的后果是什么。
**硬性要求**：必须给出「不做这一步会发生什么」的反面场景。

### 【② 核心原理】（What / How）
- 概念定义 → 数学形式（有公式必给公式，并解释每个符号）→ 直觉类比 → 工程取舍。
- 涉及架构/流程的，**优先用图讲**（示意图、结构图、曲线图），而不是堆文字。
- 必须回答："为什么是这个方案？还有哪些方案？为什么不选它们？"

### 【③ 代码】（Do）
- 给出**完整文件**（含落盘绝对路径），而不是"把这里改成那样"的碎片。
- 关键行**逐行中文注释**；非关键的样板代码可简化但要能跑。
- 代码必须满足第 4 节全部工程规范。

### 【④ 运行与验收】（Check）
- **运行命令**（可直接复制执行）。
- **预期输出**（关键日志/指标长什么样，"正常"的判据是什么）。
- **自检清单**（3–5 条，我可验证的、可量化的）。
- **常见报错 → 根因 → 修复**（至少覆盖本步最可能踩的 2 个坑）。

### 【⑤ 面试延伸】（Interview）
- 2–4 个**校招高频考点**（大模型应用岗 / 推理部署岗 / 算法岗）。
- 每个考点给出：**题目 → 答题骨架（分点）→ 面试官可能的追问方向 → 加分回答**。
- 考点必须**与本步强相关**，不夹带无关八股。

## 4. 代码工程规范

### 4.1 目录
```
F:\Qwen3-2B\radar-agent\
├── docs\             # 规范、勘察报告、每阶段交接文档
├── configs\          # 所有超参（yaml/json），禁止硬编码进脚本
├── src\              # 可复用模块：数据、检索、训练、评测、推理、Agent
├── scripts\          # 可执行的入口脚本（thin wrapper）
├── data_raw\         # 原始知识源（PDF/教材/论文）—— 只读，永不修改
├── data_processed\   # 解析/切分/tokenize 后的中间产物（可重建，不进版本库）
├── outputs\          # 训练与实验产物：checkpoint、日志、指标、图
├── reports\          # 面向人的报告与可视化
└── logs\             # 运行日志（UTF-8 显式落盘）
```
- **模型资产不动**：基座模型仍在 `F:\Qwen3-2B\dir\`（config/tokenizer/safetensors），代码里通过配置项 `model.base_dir` 引用**绝对路径**。
- **原始知识源只读**：`data_raw\` 下的文件不做任何原地修改。

### 4.2 编码
- Python **3.12**，专用环境 **`qwen3vl`**（独立 conda env，见 §9.1）。**不得污染 `E:\Miniconda` base**（`med-sft` 项目正在使用）。
- 路径统一用 `pathlib.Path`；**不出现硬编码盘符散落在代码里**，集中在 config。
- 所有脚本：`argparse` 提供参数 + config 文件双入口；带 `--dry_run` 模式。
- **禁止静默失败**：异常必须打印可诊断信息（形状、dtype、显存占用、报错原文）。
- 类型注解 + 关键函数 docstring。

### 4.3 可复现
- **固定随机种子**（默认 `seed=42`），并在启动日志里打印 seed / torch / cuda / transformers / peft 版本 + git 状态。
- 每次实验输出独立目录 `outputs/<exp_name>_<timestamp>/`，内含 `config.yaml`（最终生效配置）、`run.log`、`metrics.json`。
- **超参、数据版本、代码版本三者必须能被同一条记录还原。**
- 检索/生成实验额外记录：**索引版本号**（语料哈希 + 切分参数 + embedding 模型版本）——这是 RAG 的"数据版本"。

### 4.4 Windows 环境适配
- **本机 bash 已损坏**（`ls`/`dirname`/`head` 不可用）→ 一律用 **PowerShell 或 Python** 执行命令。
- **PowerShell `*>` 重定向写成 UTF-16**，日志会乱码 → 脚本必须用 `logging.FileHandler(encoding="utf-8")` 自己落盘日志。
- 不生成含非 ASCII 路径的 `.ps1` / `.bat`（编码会乱）；用 `.py` 脚本或直接命令行调用。
- DataLoader `num_workers=0`（Windows 多进程 spawn 易出坑），靠 `dataloader_num_workers` 配置项控制。
- 训练前打印 `torch.cuda.mem_get_info()` 基线；**OOM 按固定顺序降级**：
  `batch_size↓ → gradient_accumulation↑ → max_seq_len↓ → 图像分辨率↓ → gradient_checkpointing 开 → 4bit 量化`，
  每次只降一级，并记录最终生效配置。**禁止"盲目调小参数直到能跑"**。
- **建 conda 环境必须钉 `setuptools<80`**：`conda create -n <env> python=3.12 "setuptools<80" -y`。
  否则 `pip install torch` 会去卸载 conda 装的 setuptools 83，而 pip 卸载是逐文件删除（实测 **≈90 KB/s**），
  表现为「不报错但几乎不动」，极易被误判为卡死而反复重来。
  > **本条的普遍意义**：这是"**静默低效**"——不崩溃、不报错、只是慢到不可用。
  > 排查手法固定为：先看日志最后一行停在哪，再用「进程 CPU 增量 + 目标目录体积增量」两个独立信号
  > 判断它是真在推进还是死锁。**不要凭感觉判断"它挂了"。**

### 4.5 训练必备
- 必须开启 checkpoint 保存（`save_steps`）+ 支持 `resume_from_checkpoint`；长训练不得无存档裸跑。
- 训练中记录：`loss`、`grad_norm`、`learning_rate`、`epoch`、峰值显存、tokens/s。
- 训练结束必须落盘 loss 曲线图。

### 4.6 静默错误优先原则
代码审查与自检的**优先级按"错误是否响亮"排序**：
- **响亮错误**（崩溃、报错、形状不匹配）→ 可交给 AI 生成，运行时自动暴露，不必逐行审。
- **静默错误**（跑得通、数字看着正常但结果是错的）→ **必须人工把关 + 断言守护**。

  本项目的高危静默错误清单（每阶段开工会对照检查）：
  | 环节 | 典型静默错误 |
  |---|---|
  | 模型加载 | `eos_token` 按版本惯例推断而非实测；chat template 与实际 tokenizer 不一致 |
  | 多模态 | 图像预处理尺寸/resize 策略不匹配 → 视觉 token 数错，模型"看得见但看错" |
  | 切分 | chunk 重叠区丢失；公式在切分处断裂；元数据（页码/标题）与实际内容错位 |
  | 检索 | 归一化不一致（索引用 L2、查询用 IP）；BM25 分词器与 embedding 侧不一致 |
  | 微调 | loss mask 边界错（把 prompt 也算 loss）；padding_side 与训练/推理不一致 |
  | 评测 | 检索命中率统计口径错（按 chunk 还是按文档）；去重后分母变了 |
  | Agent | 工具调用解析用宽松正则，把"提到工具"误判为"调用工具" |

- **判断与取舍**（评测口径、切分粒度、模型选型、是否上 Reranker）→ **决策权必须在使用者**，AI 只提供选项与代价分析，不得代替拍板。

## 5. 实验与验证规范（反"自欺欺人"条款）

1. **每个阶段有 Definition of Done（DoD）**，且必须量化。DoD 未达标 → 不进入下一阶段。
2. **禁止编造指标**。所有数字必须来自实测日志；无法实测的写「未验证」，绝不写"约等于/大概"。
3. **必须有对照组（baseline）**。任何"微调/加 Reranker/换切分后有提升"的结论，必须给出**同条件**的前后对比。
4. **语料与评测集隔离**：评测问题集（含答案与证据句）**永不参与微调训练**；训练前做一次 train 与 eval 的**重叠检测（去污染）**。
5. **评测要分层**，**检索指标与生成指标必须分开报告**：
   - 检索层：`Recall@k`、`Precision@k`、`MRR`、`nDCG@k`
   - 生成层：忠实度（faithfulness）、答案相关性、引用正确率、幻觉率
   - 规则层：格式合规率、拒答率、引用格式覆盖率
   - **单一指标不下结论。**
6. **诚实报告副作用**：微调常带来通用能力下降（灾难性遗忘）与**指令跟随格式退化**。我会主动测并报告，不含糊。
7. **随机性说明**：训练与生成均有随机性，单次结果不构成结论；关键结论至少 2 个 seed / 3 次重复并给出波动范围。
8. **断言式自检**：每个阶段脚本必须包含机器可执行的断言（`src/checks.py`），覆盖：
   - **物理/逻辑约束**：显存总量 > 空闲量、显存峰值 ≥ 当前占用、分位数单调、率值单调等；
   - **交叉信源校验**：关键数值必须与独立来源比对（如进程内显存 vs `nvidia-smi`）；
   - **跨阶段契约**：为下一阶段铺路的中间产物必须被显式验证（如"检索返回的 chunk_id 必须能在索引里真实取回原文"）。

   断言分级：`critical`（失败则结果不可信，脚本以非零退出码结束、不进入下一阶段）与 `warning`（可疑，需人工确认）。**任何断言失败都必须写入报告，禁止静默跳过。**
9. **性能实验报告规范**：任何性能数据必须满足：
   - **延迟与吞吐必须成对报告**。只报 tok/s 不报延迟、或只报 TTFT 不报 ITL，视为无效数据；
   - 必须给出**成本代理指标**：至少包含**显存峰值**，并尽可能包含 **`nvidia-smi` 实测功耗**；
   - 必须报告 **P50 与 P99**，不只报均值 —— 长尾决定用户体验；
   - 任何对比实验必须**先声明"只改了一个变量"**，并给出完整实验条件（模型、量化等级、引擎与版本、并发度、prompt/输出长度分布、解码参数）；
   - 单次测量不足以定论，关键结论至少重复 3 次并给出波动范围；
   - **优化前后必须有同条件对照**，"感觉变快了"不是结论。

10. **RAG/Agent 专项验证规范（v1.0 新增）**
    - **先建"无检索基线"**：同一模型、同一 prompt 模板、同解码参数下，先测**不挂检索**的裸答表现，再测挂检索的表现。**没有这个差值的 RAG 报告是无效的**——你无法证明检索带来了什么。
    - **检索质量与生成质量解耦诊断**：答案错时，必须能回答"是**检索没召回**、还是**召回了但模型没用**"。方法：构造**"给定黄金上下文"**的对照组（把正确答案的证据句直接塞进 prompt），若此时答案正确率显著上升 → 瓶颈在检索；若仍错 → 瓶颈在生成/微调。
    - **引用必须可溯源、且可机器验证**：每条答案的引用必须能映射回真实 chunk（`chunk_id`），断言检查引用 id 存在于索引中，**引用正确率 ≥ 阈值**（阈值由你拍板）。禁止"看起来引用了"。
    - **幻觉率必须实测**：构造一批**知识库中不存在答案**的问题（"不可答问题集"），测模型是否诚实说"资料中未找到"，还是编造。**这个数字不测就不准写进报告。**
    - **Agent 工具调用必须有确定性回归**：把工具选择与参数解析写成**可断言的用例集**（输入 → 期望工具名 → 期望参数），用**严格结构化解析**（不用宽松正则），防止"提到工具"被误判为"调用工具"。
    - **端到端延迟必须拆段**：`查询改写 → 检索 → Rerank → 生成` 各段耗时分别记录。RAG 的 P99 往往死在某一小段上，不拆开就找不到。

## 6. 交互节奏规范

- **小步快跑，一步一确认**：每次只推进一个**可独立验证**的阶段，输出后停下来等你的反馈（"继续/有疑问/换方案"），不连续推进多阶段。

- **预算预告**：动手前告知预估耗时、显存峰值、下载量、磁盘占用。超预算立即暂停。
- **失败处理流程**：先诊断（给出根因假设 + 验证方法）→ 再解释为什么错 → 再修。**不允许"试错式瞎改"**。
- **进度透明**：多步骤任务用任务清单跟踪，开始前标记进行中，完成即标记完成（不攒批）。

## 7. 事实与诚实规范

- **环境实测优先**：结论基于本机实际探测结果，不基于"通常情况"。
- **不确定就明说不确定**，并给出**验证方法**（可执行的命令），而不是给一个模糊的猜测让你信以为真。
- **存疑项显式标注**，例如 plan.txt 写的"Qwen3.5-2B"与实际模型身份的偏差（见 §11 已修正项）。
- 引用外部知识（论文、官方文档、API 行为）时说明来源；版本相关行为标注版本号。
- **模型能力不吹**：`Qwen3-VL-2B` 是 2B 量级模型，在复杂雷达公式推导、多跳推理上**必然**弱于大模型。凡是它做不到的，我如实写进报告，不用"基本可用"糊过去。

## 8. 安全与合规规范

1. **数据合规**：`data_raw\` 下的教材/论文版权需由你确认；**本项目不对外重新分发原始语料**；如需分享，只分享脚本、配置与自建评测集。
2. **敏感内容**：雷达/遥感涉及专业知识，**不得将未公开的内部资料上传到任何第三方 API**（包括用云端 LLM 做评测时）。如确需云端裁判，必须先确认语料可外发。
3. **不夸大用途**：明确本项目的用途是**技术学习与研究**，禁止宣称可用于任何真实业务决策场景。
4. **不伪造引用**：RAG 输出的引用必须来自检索到的真实切片；**禁止让模型"编一个看起来像的出处"**。评测中会专门测这一项。
5. **模型卡**：最终交付包含 Model Card，写明数据、训练方式、已知局限、误用风险。

### 9.2 风险清单

| 风险 | 等级 | 缓解措施 |
|---|---|---|
| 8GB 显存 OOM | 高 | LoRA + 梯度检查点 + 梯度累积；固定降级顺序；先估后跑 |
| **多模态微调显存放大** | 高 | 视觉塔全程冻结 + `no_grad`；限制输入图像分辨率；主链路走纯文本（已拍板） |
| **MinerU 解析质量不可控** | 高 | 公式/图表解析是雷达教材的难点；先小样人工抽检，再决定是否全量 |
| **2B 模型能力天花板** | 高 | 复杂推理必然弱；评测如实报告；必要时讨论"是否该换更大基座"（决策权在你） |
| **无通用 LLM 当裁判** | 中 | RAGAS 需 LLM judge；本地 2B 作裁判噪声大 → 需专门决策（见 §12 D4） |
| Windows + bitsandbytes 兼容性坑 | 中 | 作为可选项；默认走非量化 LoRA |
| 灾难性遗忘 / 指令格式退化 | 中 | 训练前后通用能力 + 格式合规抽测并如实报告 |
| 长时间占 GPU（笔记本发热/掉电） | 低 | 分阶段短跑，随时可断点续训 |
| **本机 bash 损坏** | 低 | 已确认，一律走 PowerShell/Python |
| 评测集自建导致"自己出题自己满分" | 中 | 评测集必须**先于**微调冻结；由你人工抽检确认质量（§5.4 去污染） |

## 零、三条不可协商的纪律

1. **证据第一**：每条题先有 `evidence.quote`（**语料原文最小必要一句**），再写题。
   **没有原文证据的题，宁可不出。** 这是本项目防幻觉的核心闸门。
   `evidence.quote` 是自由文本，校验器**只管它存在、不管它真假** —— 编造出处会**静默通过**，
   所以这是**自律**，不是机器约束。编了就是污染整个训练集。

   **quote 的精确写法**（2026-09-15 用 `scripts/p3_audit_units.py` 回搜全语料后定的规矩，
   既有 61 条里有 15 条不合规，别重蹈）：

   - ✅ **逐字照抄一句完整原文**，不转述、不概括。
     反例 ✗："线性调频信号的脉冲压缩处理可以获得大的时宽带宽积"（概括，搜不到）
     正例 ✓："信号的脉冲压缩比或时宽带宽积为 D = Δ·B"（教材原句）
   - ❌ **不要加** `[p75]` `[A]` `[B]` `[脉冲雷达]` 这类自编标签/页码前缀 —— 语料里没有这些标记。
     页码写进 `evidence.source`，quote 里只放原文。
   - ❌ **不要拼接**（用"……"连两句），也不要把公式与说明混在一起。要引两句就出两条题。
   - ❌ **`unanswerable` 题**：quote 别写"教材从未给 X 的具体数值"这类**你自己的论证** —— 那不是原文。
     论证写进 `notes`，quote 留空或写检索结论（"已检索 X，全书无命中"）。
   - ⚠️ **公式可规范化，但要保守**：把 `$\chi \big ( \tau , f _ { \mathrm { D } } \big )$` 写成 `χ(τ, f_D)` 属于合理
     规范化（核验脚本会因为 LaTeX 差异判未命中，属**可接受**的例外），
     但**散文部分必须逐字**。拿不准就**直接抄含 LaTeX 的原文**，最安全。
   - 🔍 **交付前自查**：`scripts/p3_audit_units.py --files data_authored/<你的文件>.yaml`，
     看输出末尾「五、证据核验」的未命中清单。
2. **真值不手写**：`calc` 的数值由 `src/dataset/formulas.py` 程序算出。你只写 `formula` + `inputs` + `unit`。
3. **"我记得没有/有"不算证据**：任何"教材里有没有这个式子"的判断，都必须用取证工具**查过**。
   （2026-09-15 U01 出过一次误判：以为教材没给 ΔR = cτ/2，查了才发现 p79 明确给了。）

### 通用字段取值（**越界 = critical**）

- `subdomain` ∈ **11 个**（2026-09-15 由 6 个扩展，见 `docs/07` §7.3）：

- `ask_style` ∈ `explicit` / `implicit` / `contrast` / `correct` / `parametric` / `clarify`
- `term_key`：可选（来自 `src/dataset/term_registry.py`）。**不确定就留空**，别猜（猜错会报 critical）。

## 五、各 task 的写法（**按草稿 spec** `logs/probe/_draft_spec_v1.yaml`）

### ① `calc`（真值程序算，最安全）

```yaml
    task: calc
    question: '雷达的距离分辨率怎么算？以信号带宽 B = 150 MHz 为例说明。'
    formula: range_resolution        # 必须是 formulas.py 注册表里的名字
    inputs: {B: 1.5e8}               # ★ 必须来自 configs/param_pool.yaml 的 train 半边
    unit: m                          # 必须与公式输出单位一致
    tol_rel: 0.01
    evidence: {source: '《机载雷达系统与信息处理》第2章 2.4.1（PDF p82）',
               quote: '雷达的距离分辨率由雷达发射信号的带宽决定。'}
    notes: >-
      可选。写"为什么出这条""与哪条题构成对照"。
```

- ⚠️ **题面口吻**：真实用户问的是"**怎么算？**""**如何计算 X？**"，不是"某雷达…求 X"。
  写成"……是怎么算出来的？以 <参数> 为例说明。"
- ⚠️ `formula` 名字和参数名**必须**与注册表一致 → 用 `p3_corpus_query.py formula` 确认。
- ⚠️ **参数只能取自参数池 `train` 半边**（评测集另用 `eval` 半边，重叠 = 泄漏）。
  池用尽时在 `configs/param_pool.yaml` **追加**，不要在 yaml 里硬写新参数。

### ② `choice` / `regime_trap`（必须给解析）

```yaml
    task: choice
    # ⚠️ 必须是 **list**，写 dict（{A: '…'}）会报 E_OPTIONS critical —— 校验器只接受 list。
    options: ['A: 匹配滤波器的输出信噪比与信号的波形（形状）有关',
              'B: 匹配滤波器的传递函数是输入信号频谱的共轭',
              'C: 匹配滤波器的输出信噪比正比于信号的峰值功率',
              'D: 匹配滤波会引入信噪比损失']
    answer: B
    explanation: '……为什么 B 对、A 错（A 是把脉冲雷达公式套到连续波上）……'
    keypoints: ['要点1', '要点2', '要点3']       # 1~3 条
```

- ⚠️ **`keypoints` 每条必须是 `explanation` 的子串**（不是 `answer` 的子串 —— 答案是单个字母）。
  不满足 → `E_KEYPOINT_NOT_IN_ANSWER`（critical）。这是最容易踩的一条。
- ⚠️ `regime_trap` = 选择题的**体制陷阱变体**：干扰项里必须放"把其他体制结论套过来"的错误答案，
  且**双信源**（陷阱项的"在本体制下成立"也要有出处）。

### ③ `concept` / `term`

```yaml
    task: concept
    answer: '匹配滤波器的输出信噪比只取决于信号能量 E 与噪声谱密度 N0，与信号波形无关。'
    keypoints: ['只取决于信号能量', '与信号波形无关']
```

- `answer` 字数上限：**concept 120 字 / term 200 字**。
- `keypoints`：**2~6 条**，**每条必须是 `answer` 的连续子串**。
- ⚠️ 常见踩法：要点写了"脉冲宽度"，答案里写的是"矩形脉冲的宽度" → 不匹配 → critical。
  **要点用答案里真实出现的措辞**。
- `term` 问法是**正向**："CA-CFAR 是什么？"（不是"给描述猜缩写"）。

### ④ `unanswerable`

```yaml
    task: unanswerable
    answer: '资料中未找到相关内容，无法回答。'
```

- ⚠️ `answer` 必须**逐字等于**上面这句（含句号），多一个字都报 critical。
- 用途：问一个**语料里确实没有**的东西（例如某型号雷达的具体参数）。
  出题前**必须**用 `search` 确认语料里真的搜不到，并在 notes 里写明"已检索 X 关键词，无命中"。

### ⑤ `contrast`

```yaml
    task: contrast
    regime: airborne_pulse
    regime_b: fmcw                    # 必填，且必须与 regime 不同
    answer: '…两个体制下的差异…'
    keypoints: ['要点1', '要点2', '要点3']    # 3~6 条（下限比 concept 高）
```

### ⑥ `clarify`

```yaml
    task: clarify
    regime: unspecified               # ★ 必须与 task=clarify 成对（双向断言）
    ask_style: clarify
    answer: '…需要先明确雷达体制才能回答……'   # ★ 必须含「体制」二字
    keypoints: ['要点1']               # 1~4 条
```

- ⚠️ 占比 **≤10%**，一个单元最多 2~3 条。

## 六、YAML 书写坑（本机已踩过）

1. **单引号字符串里的单引号要写两个**：`question: '…… don''t ……'`。
   更稳妥：整段用单引号包裹，内部不出现单引号。
2. **`notes` 用 `>-` 折叠**：内部**不要**出现 `: ` 开头的行、不要缩进错乱。
3. **禁止 Markdown 排版符**：`**加粗**`、`## 标题`、`| 表格` **不得**出现在
   `question` / `answer` / `explanation` / `options` 里 —— 会静默进训练集，模型会学着输出星号（D-P2-16）。
4. **禁止** `<|im_end|>` 等保留标记出现在任何文本里（会被编码成真 token，静默切断样本）。
5. **禁止重复键**：YAML 允许重复键且后者静默覆盖 —— 框架有 `E_DUP_YAML_KEY` 断言会拒绝加载。
6. **数值用科学计数法**：`1.5e8` 而不是 `150000000`（可读性）。

### 交付标准

- ✅ `critical = 0`（硬门槛，一条都不能有）
- ⚠️ `warning` 逐条说明接受/已修。常见几条：
  - `W_NO_SHORTCUT_BREAKER`：本批全是 explicit 问法 → 补 implicit/correct/contrast 问法的题。**这条要修。**
  - `W_REGIME_MISMATCH`：题面有体制表面词却标了 `universal`（或反之）→ 按 §五 调整，通常要修。
  - ⚠️ **`W_QUOTA`（子方向占比 >40%）—— 单元级属"预期告警"，可直接说明后接受，不要硬洗。**
    原因：我们**按章分单元**出题，单元内必然集中在章主题（第5章就该 78% 是雷达方程）。
    R7 的本意是防止**整个数据集**偏科，判定看**全局**（`p3_audit_units.py` §3.3），不是单批。
    ⚠️ 为压低单元内占比而把题**错分类**（例如把雷达方程题硬挂 misc）是**得不偿失** ——
    那会让统计本身失去意义。**只有当你确实分错了类才改。**
    （2026-09-15 实测：第7章 misc 改名为 array_processing 后，告警从 82% 变成 82% —— 比例没变，证明是粒度问题。）
- ✅ 每条都有 `evidence`（`unanswerable` 也要有，写"检索 X 无命中"）
- ✅ `calc` 参数全部来自参数池 `train` 半边
- ✅ 每知识点 ≤ 6 条，且落在不同题型/问法

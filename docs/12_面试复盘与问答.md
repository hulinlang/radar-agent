## 一、电梯陈述（30 秒版）

> 我做的是一个**本地部署的雷达领域问答助手**。核心问题是：一个 20 亿参数的小模型，
> 既记不住专业教材的细节，又算不对雷达公式。
> 我的解法分两步：一是**微调**，教它"答得像样"——用 1074 条自建数据做 LoRA；
> 二是**给外挂**，教它"该查就查、该算就算"——建了 3659 条知识卡片的混合索引，
> 再让它自己决定什么时候检索、什么时候调计算器。
> 最终小模型的计算题正确率从 **0.28 提到 0.89**，该说"不知道"的时候从 **几乎不说变成 100% 会说**。
> 但我也实测出一个反直觉的结论：**开了检索之后综合得分反而降了 7.5 个百分点**，
> 这是我最想讲的部分。

**2 分钟展开版**（面试官让你细说时按这个顺序）：

1. 问题定义（小模型的两个短板：记不住 + 算不准）
2. 数据从哪来（363 页教材 + 35 篇英文论文，MinerU 解析，自建 1274 条题目）
3. 微调做了什么（LoRA 0.82% 参数，冻结视觉塔）

5. Agent 怎么做的（ReAct 自主决策 + 六重护栏）
6. **评测结论，包括负面的**（这是差异化）

## 二、全链路与关键数字

```
PDF 语料 → MinerU 解析 → 块级切分 → 混合索引 ┐
                    ↘ 自建题目（答案由程序算） ┴→ LoRA 微调 → ReAct Agent → 演示界面
```

| 阶段 | 做了什么 | 关键数字 |
|---|---|---|
| **P0** 核验 | 数清基座参数、确认 tokenizer | 2,127,532,032 参数；eos 是 `<|im_end|>` 不是 `<|endoftext|>` |
| **P1** 引擎选型 | HF vs llama.cpp 量化对比 | 吞吐 ×5.2–6.6，P99 延迟改善 7.5×，**TTFT 基本不变** |
| **P2/P3** 数据与语料 | 解析 864 页，自建题目 | 训练 1074 + 评测 200；24 条公式注册表；引用 1308/1308 可溯源 |
| **P5** 微调 | LoRA 只训语言侧 28 层 | 可训练参数 17.43 M（**0.82%**）；8 GiB 卡跑 40 分钟 |
| **P4** 检索 | 切分 + 混合索引 | 3659 条卡片；**R@5 75.3% / R@10 83.3% / MRR 0.590** |
| **P5b** 工具调用微调 | 教它"该调才调" | 调用率 97.0%、工具选对 94.5%、**常识题误调 0%** |
| **P6** Agent | 三工具 + 四门解析器 + ReAct | 空检索阈值实测标定为 0.55（无关/相关完全分离） |
| **P7** 端到端评测 | 200 题四组对照 | ⚠️ 综合 **0.370 → 0.295**；引用 130 个、**编造 0 个** |
| **P8** 演示 | FastAPI + 单页界面 | 能看到每一步调了什么工具、耗时多少 |

## 三、⭐ 我做的判断（面试最想听的）

按"我面临什么选择 → 为什么这么选 → 代价是什么"来讲。

### 判断 1：不做思维链（CoT）

先去实测基座有没有 thinking 模式 —— 没有。硬造 CoT 数据等于让模型学一套它没见过的输出格式。
**代价**：放弃了复杂推理上的可能收益。**依据**：`docs/05` §5.8 实测。

### 判断 2：微调前移、RAG 后置

原计划是先搭 RAG 再微调。我反过来：**先微调再接检索**。
理由是——这样"无检索基线"是干净的：先知道模型**自己**能答到什么程度，
再测检索带来的增量。否则两个改动叠在一起，说不清谁贡献了多少。
**这个决定后来救了我**：P7 能明确说出"检索让综合分降了 7.5 个百分点"，正是因为有这条干净基线。

### 判断 3：LoRA 只训语言侧，视觉塔和词表全冻

316 个张量冻掉，只给语言侧 28 层的 7 类投影加 LoRA。
**为什么**：主链路是纯文本问答，视觉塔占 19.1% 参数却用不上；动了它既浪费显存又有遗忘风险。
**实测佐证**：我试过给视觉-语言对齐层也加 LoRA（方案 B1），**没有增益**，出局。

### 判断 4：判分口径自己定，不用现成的

发现 3-gram F1 **对数值错误几乎免疫**：把参考答案里的 19.1/20/26 km 全改成 88.8/91/97 km，
句式一字不改，F1 仍有 **0.717**。→ 光看 F1 会把"算错了"判成"答对了"。
于是自己加了**数值命中率**（±2% 容差）和**拒答判定**，形成口径 v3。
**这是面试可以主动讲的一个点**：指标本身需要被验证，不能拿来就用。

### 判断 5：计算器改成"传表达式"，不传公式名

最早设计成"传公式名 + 参数名"（`{formula: "range_resolution", inputs: {B: 1e8}}`）。
30 道题里 **13 条（43%）栽在猜名字上**：漏传参数、参数名猜错（`bandwidth` 应为 `B`）、臆造不存在的公式名。
改成只传算术表达式（`{expr: "3e8/(2*1e8)"}`）后：
- 这部分失败 **13 → 0**
- 计算题得分 **0.400 → 0.633**

**根因洞察**：模型其实**会列式且列得准**（29 条里 20 条式子正确，91%），是接口把它搞乱的。
→ **不是模型笨，是接口设计错了。** 这个结论有探针数据支撑（90.9% 的式子交给计算器能算对）。

### 判断 6：自己做的东西，实测是负收益就关掉

用户提议"给公式也加个名字索引"（像 `Fig. 1` 那样）。方向上对，我实现了，但实测：
全集 MRR **0.590 → 0.573**（掉）。→ **默认关闭，代码保留，注释里写明为什么关**。
追问时能接住：计算题子集上确实 +35%，但全集是负的，且两种标注口径给出相反结论——**靶子在动时不该急着调参**。

## 四、⭐⭐ 负面结果（最能体现水平的部分，主动讲）

### 负面 1：开了检索，综合得分反而降了

| 指标 | 不给工具（A） | 完整系统（B） | 差 |
|---|---|---|---|
| 综合得分 | **0.370** | 0.295 | **−0.075** |
| 该说"不知道" | **94.7%** | 78.9% | **−15.8 pp** |
| 计算题 | 0.733 | 0.400 → 0.633（改接口后） | −0.333 → −0.067 |
| 引用溯源 | 0 个 | **130 个，编造 0 个** | ⭐ 唯一确定性收益 |
| 延迟 | 5.2 s | 22 s（工具只占 32 ms） | 4.2× |

**根因**：检索几乎总能返回点东西 → 模型认为"有依据" → 不再说不知道。
这是小模型 RAG 的经典幻觉风险，不是参数没调好。

**我怎么证明的**：跑四组对照（A 无检索 / B 完整 / C 给正确段落 / D 给随机段落），
C 组也没回到 A 的水平 → 说明瓶颈不在"翻不翻得到"，而在"翻到之后会不会用"。
→ **结论：收益的天花板在模型和数据侧，不在检索策略侧。**

### 负面 2：检索怎么调，收益都是个位数百分点

| 改了什么 | 收益 |
|---|---|
| 单路 → 双路融合 | R@5 +5.2 pp |
| 加图号/表号专用索引 | 对全集 **0 影响** |
| 多加 1639 条英文文献 | 教材题 **0 影响**（至少证明不会变差） |
| 公式概念索引 | **负收益**，已关 |

而数据侧的问题是几十个百分点量级（OCR 公式写错、标注错位）。
→ 这是我给这个项目下的最重要判断，**也是面试最值得抛的观点**。

### 负面 3：视觉读数能力完全没有提升

数值命中率 0.467 → 0.467。
**不是"瞎"**（能读出合成图里的坐标轴和目标数），也**不是分辨率问题**（已到原生上限）。
真因是**视觉训练样本只有 83 条**。给对齐层加 LoRA 也无效。

### 负面 4：中文提问查英文论文效果差

R@5 只有 24.2%。我跑了一组对照分离原因：

| 检索范围 | R@10 |
|---|---|
| 全库 | 39.4% |
| 只翻英文论文 | **63.6%** |

→ 两层原因：中文语料把位置抢了（差 24 pp）+ 跨语言本身有上限（63.6% 也远低于理想上界）。
**方法论**：凡是"某类内容翻不到"，先跑一遍"只翻这类"来分离原因——
"被别的语料抢了"和"它本身能力不行"是两个问题，解法完全不同。

## 五、追问预案（Q&A）

**Q：为什么不用 GPT / 调 API？**
这个项目要验证的恰恰是"**2B 模型在垂直领域能做到什么程度**"。
换 GPT 就没这个问题了，也就没有后面这些结论。另外数据里有受版权保护的教材论文，不外发是硬红线。

**Q：RAG 开了反而变差，那你做它干嘛？**
三个理由：① 引用溯源是实打实的收益（130 个出处，编造 0 个），这在专业领域是刚需；
② 变差的原因已经定位清楚（模型读完片段后过度自信），这是**模型侧**问题，不是检索的问题；
③ 我把负面结果量化出来了，这本身就比"据说 RAG 有用"有价值。

**Q：数据从哪来？会不会有版权问题？**
教材和论文是我自己整理入库的，题目是我按章节出的，**答案由程序按公式算出**，不手写。
语料切片和数据集**没有随仓库分发**（README 里写明了重建方式和版权提示），只上传了模型适配器。

**Q：你怎么证明模型是"学会了"而不是"背下来了"？**
三层防护：① 训练集和评测集物理隔离，且做过去污染检测（三项全干净）；
② 评测集全程不参与调参；③ 参数池 train/eval 硬隔离（239 组参数不重叠）。

**Q：为什么 LoRA 不用全参微调？**
8 GiB 显存，全参微调 2B 模型放不下。而且 LoRA 只训 0.82% 参数，
40 分钟就能跑完一轮，让我能快速迭代 6 个版本（tool1→tool6）——**迭代速度本身就是收益**。

**Q：幻觉怎么解决的？**
三层：① 空检索阈值 0.55（实测标定，无关/相关完全分离），查不到就明说；
② 引用必须带 chunk_id，服务端会校验编号是否真实存在（130 个里 0 个编造）；
③ 微调教它拒答（从 0.2% 提到 100%）。

**Q：你的项目和调个 LangChain demo 有什么区别？**
区别在**评测和归因**：我给每一步都留了对照（A/B/C/D 四组），
每个结论都有数字，包括自己做的东西被证明是负收益然后关掉。
demo 是"跑通了"，我这里是"知道为什么通、也知道为什么不通"。

**Q：如果给更多时间和算力，你会怎么改？**
① 建公式级真值标注（现在 41% 的计算题失败无法归因）；
② 视觉训练样本从 83 条扩到 500+；
③ 换/微调 embedding 解决跨语言上限；
④ 用更大的基座（7B）验证"天花板在模型侧"这个判断。

## 六、踩过的坑（体现工程严谨性，挑 2-3 个讲）

| 坑 | 后果 | 怎么发现的 |
|---|---|---|
| 工具观察回灌用了 `role="function"` | 内容被**静默丢弃**，Agent 循环失效 | 对比 role="tool" 才看到差别 |
| 3-gram F1 对数值错误免疫 | 算错了也判高分 | 故意改坏参考答案，F1 仍有 0.717 |
| MinerU 导出≠可用 | 把 $u_2$ 认成 $u_1$ | 人工抽查（所以公式必须人工核对） |
| 教材本身也会算错 | p42 把四次方根写成 50%（应为 56.2%） | 过了一遍算术 |
| 配置键名不一致 | 改了参数**不生效**还不报错 | 逐字核对 DEFAULTS 与 yaml |
| 显存看 reserved 而非 allocated | 训练被误杀（8.7 > 8.0 物理显存） | allocated 其实只有 4.2 |

**共性**：**没有一个是崩溃，全是"我以为对"**。对策是双信源交叉 + 断言 + 实测。
